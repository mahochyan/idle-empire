# 阶段5 · 验证、灰度与回滚设计

> 静态托管约束下的现实形态：无服务端 AB 平台 → **本地分桶 + 构建分支灰度 + 导出抽样**。此法有噪声与幸存者偏差（只有愿意导出的玩家贡献数据），全部结论降级为"方向性证据"，本文档所有实验按此前提设计。

## 1. 分桶与灰度机制

- **分桶**：`bucket = FNV1a(deviceId + 实验ID) % 100`，deviceId 首访生成存 localStorage；分组写入每条埋点事件。纯前端可复算（导出样本后可离线重放分桶）。
- **灰度通道**：GitHub Pages 双分支：`release`（默认体验）与 `beta.<实验名>`（自测链接+社区小流量）。玩家主动开 beta 链接=选择偏差大——**仅用于稳定性验证**；数值/平衡类实验一律走同包内 localStorage 分桶（双逻辑并存一版），保证随机可比。
- **流量节奏**：每实验 beta 3 天（崩溃/NaN/存档异常=0）→ 同包分桶 20% vs 80% 对照 14 天 → 达标全量（保留 flag 一个版本周期）。

## 2. 实验设计（逐批）

| 实验 | 分组 | 主指标 | 护栏指标 | 观察期 | 停止条件（任一即停） |
|---|---|---|---|---|---|
| E1 科技点学者线 | 对照组无学院；实验组有（1-A/1-B） | D3 首研率≥60%、D7 留存差 | 食物消耗通胀>25%、学院人口挤占采集致军队萎缩（兵数中位降>20%）| 14d | D7 实验组 ≤ 对照；经济曲线越过推演带 |
| E2 Boss 修复 | 分桶 bossHpMult {0.6×, 1×, 1.6×} 三档 | Boss 重试中位 1~3、D7 无恶化 | Boss 关放弃率>40%（挫败流失）| 14d | 任一档放弃率>40% 即砍该档 |
| E3 离线收益 | 系数 {0.4, 0.55} × 封顶 {4h, 8h} 四桶 | 次日回访间隔中位↓、日均会话≥2 | 在线游玩时长降幅>20%（离线替代在线）| 21d | 总时长净降；上线日即回滚 0-B 前版本可玩 |
| E4 扫荡 | 有/无 × 日限 {5, 10} | 日均会话↑（时间税↓→多次短会话）| 日均时长降幅>35%（玩不动了）| 14d | 时长雪崩→日限降 5 或下线 |
| E5 日课 | 有/无 | 参与率≥45%、完成日次留差≥10pp | 完成失败日的挫败流失（对比未参与组留存不可显著更差）| 21d | 参与率<20%（设计失败，重做奖励非删系统）|
| E6 关卡再平衡包 | 整包 {旧 levels, 新 levels} 分桶 | 流失节点分布右移（L40+ 占比）| 旧档玩家章节内难度跳变投诉/弃坑尖峰 | 21d | 新包 D3-L50 段流失>旧包即整包回退 |

## 3. 回滚设计（每项改动=可关开关）

**总原则**：所有批次改动挂在 `CFG.flags`（feature flag，构建时可固化）；存档字段全部"新增可选字段+load 兜底默认值"→ **任何回滚不需要动玩家存档**（新增字段被旧版本 load 忽略，天然向下兼容）。

| 项 | 回滚动作 | 数据后果 |
|---|---|---|
| 埋点/导出 | flag 关 | 无 |
| 学院/学者线 | flag 关：tech 产出停止，已研究节点**不回滚**（研究永久原则，防剥夺感）；学者分配自动回退为闲置 | 科技点存量冻结不清零 |
| bossHpMult | 恢复旧 levels 数据文件（git revert 单 commit）| defeated 不受影响（不重算历史）|
| 离线收益 | flag 关=无报告卡，ts 字段留存 | 无 |
| 扫荡 | flag 关 | 无 |
| 交易所 | flag 关，存量代币/资源保留 | 无 |
| 成就/图鉴 | 纯展示层，随时可关 | 无 |
| 关卡再平衡 | 新旧双配置文件并存 + flag 选择（不发版即回退）| 见 E6 |
| 存档 v 字段 | v 只增不减；旧版本读新档靠字段忽略 | 极端情况导出文本可脚本迁移（迁移脚本随 0-B 交付）|

**回滚执行 SLA**：Pages 形态=git revert + push（分钟级）；灰度期间出问题只动 beta 分支，release 零污染。

## 4. 监控面板（静态托管的现实替代：导出聚合脚本）

- `_ops/aggregate.js`：读入导出的 JSON 样本（拖文件即出）→ 留存表/漏斗（新手链 4 步）/E 组对照差值/异常事件（NaN 资源、tick 跳变、save 解析失败）列表。
- 告警语义（人工周报即可）：save_parse_fail>0.5%、NaN 埋点>0、会话时长 P99>4h（挂机脚本征兆）。

## 5. 诚实边界声明

1. 无服务端→无法获得全量分母，所有比率是"导出样本内比率"；留存绝对值不可信，**组间差值可信**（同一选择偏差两边同源）。
2. 分桶在玩家清 localStorage 后重置→长期实验有分桶漂移；90 天级结论以版本前后队列对比（interrupted time series）为主，分桶 AB 只承担 14~21 天窗口。
3. 全部目标值（03 §7）是无基线假设；第一批实验的唯一硬承诺是 E1 的"tech_unlock>0"（修复前后 0→正数是逻辑必然，不依赖统计）。
4. 若用户后续接入任意 BaaS（哪怕是只写不读的收集端点），0-A 埋点的 POST 占位与 05 全套即刻升级为真实数据版——本方案两套指标定义已对齐，无缝切换。
