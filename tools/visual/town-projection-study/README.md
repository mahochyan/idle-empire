# 主城原画投影深度样板（未接入游戏）

## 范围与判断

这是基于现有基础时代全景的一次**隔离技术实验**。它没有修改 `hd2d.js`、`ui.js`、`visual.css`、`index.html`、Android 工程、游戏状态或存档；九时代运行地图仍使用当前资源。

对照图：[360×200 原画／默认镜头／旋转 8°](../../../hd2d-previews/qa-town-projection-comparison-360x200.png)。默认镜头保留原画的视觉质量，8° 可以看到轻微视差，未出现明显的双重主楼。**验收结论：只能作为固定镜头的三维浮雕候选，不满足完整三维城镇与可从多角度观看的建筑要求，不接入运行资源。**

## 实际三维内容

- 原画的中央区域贴在一个有连续深度的三角网格上，手工深度函数把屋脊、屋面、墙、栅栏和台阶抬起；网格有 8,181 顶点和 16,000 三角面。8° 旋转使用真实的 WebGL 三维矩阵和深度缓冲，产生有限视差。
- 背景是单张平面。中央清场使用现有 ImageGen 候选图与原画在片元着色器中混合；浮雕在原始机位盖住清场区域，因此没有原主楼残影。纹理没有写出或改绘成新位图。
- 建筑的侧面、背面、屋檐内部和遮挡后方都不存在可信素材。手工深度是近似高度场，不是可以自由旋转的独立建筑 GLB。原画内已有的光影被一起投影；当前像素保真材质不响应实时主光源，也没有真实投影阴影。因此不能把这个样板称为“完整三维城镇”。

## 画质与成本

在 Edge/WebGL 中以 1024×525 原始像素比较渲染结果与原 PNG，RGB 每通道绝对差取平均，范围 0–255：

| 机位 | 全图 | 中央 x350–675/y90–360 | 其余区域 |
| --- | ---: | ---: | ---: |
| 默认 0° | 0.1 | 0.2 | 0.0 |
| 绕中央旋转 8° | 5.3 | 28.6 | 0.7 |

8° 中央差值主要反映有意的视差和露出的清场背景，不能当作默认画质误差。360×200 对照中原画构图和色彩基本保持，但旋转后主楼边缘与后方场景的细节仍不够稳定，放大和更大旋转角度会暴露浮雕本质。

两张 1024×525 RGBA 贴图的理论未压缩 GPU 占用约 4.3 MB，另有 framebuffer、几何和驱动开销；PNG 文件分别是 1,789,502 与 1,282,716 字节。一个背景绘制和一个浮雕绘制，未测设备 FPS、温度和 Android 十分钟稳定性。要覆盖九时代及七个地标，需要分别制作真实可见侧面的三维模型和符合统一机位的前景/背景素材；不能把这个深度函数直接复制到各时代。

## 复现

在仓库根目录运行：

```powershell
node --check tools/visual/town-projection-study/prototype.js
node --check tools/visual/town-projection-study/capture.js
node tools/visual/town-projection-study/capture.js
```

本次三条命令均退出 0。捕获脚本在临时本地 HTTP 端口启动 Edge，无外网请求，完成后关闭服务。截图是实时浏览器渲染，不是概念稿。基线为 `master` / `406bce4dc86a7d12f442ceebe5143ec9fa6f6e6d`，原有工作树改动均保留。若要撤销本实验，只需移除本目录及上述 QA 图；游戏运行画面和 `rts_save` 不涉及回退。
