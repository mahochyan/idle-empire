# 基础时代主楼：原画投影到实体几何的独立样板

这是针对 `assets/art/scene/town-base.png` 中央主楼的一次美术技术试验，**没有接入游戏、Android 包或存档**。可编辑源是 `prototype.js` 里的逐块网格定义；浏览器直接生成 Three.js 网格，没有 GLB。`index.html` 提供交互视图：鼠标在画面上左右移动可改变方向光；查询参数 `yaw=-8..8` 控制样板旋转角度。预览必须经本地 HTTP 打开，以便 WebGL 读取同源 PNG。

## 结构与测量

主楼由两个厚屋坡、三角形前檐、前后有深度的墙、十段有中心空洞的石院环、七级台阶和独立木栅柱组成。每个主要构件有正面、反面和侧面闭合网格。不存在承载整栋主楼画面的单张透明立面。去贴图视图用于直接检查屋坡法线、墙和石阶体积。为了控制移动端成本，同材质小面会合并成一张网格。

在本机 Edge 无头 WebGL（SwiftShader）实测：

| 镜头 | 三角面 | 闭合构件 | 网格批次 | 绘制调用 | 原画 RGB 差，全图 / 中央 / 中央外 |
| --- | ---: | ---: | ---: | ---: | ---: |
| −8° | 1,150 | 79 | 5 | 6 | 3.87 / 23.47 / 0.018 |
| 0° | 1,150 | 79 | 5 | 6 | 1.44 / 8.68 / 0.018 |
| ＋8° | 1,150 | 79 | 5 | 6 | 3.91 / 23.73 / 0.018 |

RGB 差是每通道平均绝对值，满量程 255；中央为原图 `x350..675/y90..360`。左右屋坡法线点积约 0.609，深度为 7..90 个样板单位。把方向光从左移至右，中央 RGB 平均变化约 0.35，证实材质响应实时光源，但幅度刻意较小。背景图和清场图分别为 1,789,502、1,282,716 字节；两张 1024×525 RGBA 贴图的未压缩 GPU 数据共约 4.10 MiB，另外还有网格、帧缓冲和驱动开销。绘制调用数字不等于实机帧率。

## 画质关卡

**结构验证通过；尚未达到正式替换质量。** 默认 360×200 构图和原画的主楼识别度保住了，±8° 能看到真正的屋坡、墙体和栅柱视差，周围原画像素几乎不变。中央默认仍与原图有 8.68/255 的平均差，屋脊、蓝旗和石墙手绘细节比原画简化；旋转后部分侧面只能显示纯色材料，局部露出清场草地。旧的高度场浮雕样板在默认机位中央差只有约 0.2，因此不能用“结构更真实”宣称这版总体画质已更好。若要在游戏中用三维城镇替换原画，需要补绘侧面和遮挡后方的贴图、精修中央逐像素轮廓，再与九时代统一机位和真实设备性能一同验收。

本样板没有 Android 真机验证，也不证明其他八个时代或七个地标完成。当前不修改运行时的 `hd2d.js`、`index.html`、`ui.js`、`visual.css`，不触及 `S`、`B` 和 `rts_save`。
