# 三维美术候选与当前 WebGL 解析器的兼容检查

这两条开发侧命令检查候选 GLB 能否被当前 `hd2d.js` 的静态 glTF 子集读取。它们不替换运行资源，不改玩法和存档，也不证明模型在手机画面里足够好看。

```powershell
node tools/visual/check-glb-runtime.mjs
node tools/visual/verify-glb-runtime.cjs
```

第一条做字节级预检：GLB 头、单一 BIN、三角网格、属性、内嵌图像、节点引用和贴图坐标是否落在现有解析器支持的范围。第二条启动独立 Edge/WebGL 页面，在本地 HTTP 响应里**临时**把 `town_hall.glb` 映射成每个候选文件，反复调用真实 `HD2D.mountTown` 并检查 `modelsLoaded===1`；其他地标 GLB 返回 404，避免把它们的成功误算成待测模型。工作区和 APK 中的文件不会替换。

2026-09-27 在 `master` / `406bce4dc86a7d12f442ceebe5143ec9fa6f6e6d` 的工作区运行：预检 **13/13** 结构可读，浏览器实际解析 **5/5** 候选可读，两条命令退出码均为 0。青铜候选有一组额外 `TEXCOORD_1`，当前材质使用 `TEXCOORD_0`，所以解析器忽略前者不影响底色贴图；脚本将其列为提示。八角主楼候选超过暂定 4 MiB 整场 GLB 预算，村落候选超过暂定 30,000 三角面与 4 MiB，均不宜未经实机性能检查直接接入。

这些测试只验证**能够解析**。现有运行地图在全景加载后隐藏三维地标，因此 `modelsLoaded===1` 不能说明候选已经显示，也不能说明其轮廓、遮挡、帧率或手机温升合格。可视画质仍以 320–430 CSS px 画面、原画并置及展开视图审查；正式包还需物理 Android 手机离线十分钟验收。当前手机不可用，这一项保持未运行。
