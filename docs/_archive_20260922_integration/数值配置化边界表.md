# 数值配置化边界表（切片 16 · D2）

> 对应规格 S6「配置驱动与静态版本化」。**本表为审计结论，不改任何数值**；"越界项"仅登记为候选，需你确认后才动。

## 1. 边界规则（本项目既有约定，来自 `CLAUDE.md` / `AGENTS.md`）
| 层 | 文件 | 允许放什么 |
|---|---|---|
| **配置层** | `config.js`、`levels.js`、`technology.js` | 一切**可调数值**：资源速率/上限、建筑成本与 buff、兵种属性、敌人与关卡、科技成本、开关表 |
| **逻辑层** | `math.js`、`garrison.js`、`ui.js` | ①公式**结构常量**（0/1/2/0.5、伤害系数）②从 `CFG` 读取的参数 ③**不得**新增硬编码阈值 |
| 测试/工具层 | `tests/`、`tools/` | 断言期望值、推演覆盖值（**不得**被游戏运行时引用） |

## 2. 审计结果（只读脚本 `tools/verify/config-boundary-audit.js`，日志 `logs/config-boundary-audit.log`）

|---|---|---|
| `math.js` | 85 | 0×358、1×109、2×22、3×13、1.0×9、0.5×8、5×8、10×8、300×7、120×7 |
| `technology.js` | 28 | 0×47、2×21、3×21、**500×15、600×11、1500×10、2000×8**（= 兵种研究树数据，**属配置层，合规**） |
| `garrison.js` | 48 | 0×77、2×17、1×14、3×13、**50×6、100×6、40×5、120×4**（= 入侵模板奖励/时长，**见 3.2 越界候选**） |
| `ui.js` | 23 | 0×107、1×13、100×8、60×3（多为格式化/布局常量，**合规**） |

## 3. 分类结论
### 3.1 合规（保持现状）
| 项 | 位置 | 理由 |
|---|---|---|
| `DAMAGE_COEF = 0.09` | `math.js@1701` | 战斗**公式结构常量**（`CLAUDE.md` 明确"定义在 math.js，驻军共用"） |
| 升级时间上限 `120` | 由 `CFG.maxUpgradeTime` 读取（`math.js` 内 `Math.min(rawTime, CFG.maxUpgradeTime||120)`） | 从配置读取，兜底字面量与配置一致 |
| 训练节奏 `perTick`、单位成本上限 | 由 `CFG.unitTrainTime` / `CFG.unitCaps` 读取 | 合规 |
| 兵种研究树所有数值 | `technology.js` | 该文件**本身就是配置层**（`CLAUDE.md`：CFG 分布在 config.js/levels.js/technology.js） |
| UI 格式化常量（`1000`/`3600`/`60`） | `ui.js@838-839` 等 | 纯展示换算 |

## 4. 纪律（写入发布检查清单）
- 新数值**必须先落 `config.js`**，再在逻辑层读取；PR/交付报告需注明配置键名
- 逻辑层出现"看起来像可调阈值"的字面量（≥10 且非公式常量）时，必须登记到本表并给出结论
- 自检：`node tools/verify/config-boundary-audit.js`（只读，输出分布供人工比对）
