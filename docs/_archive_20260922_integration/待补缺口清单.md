# 待补缺口清单（阶段 1 产出）

口径：本项目**无服务端**（用户确认），"后端能力"以本地等价实现落地。以下为**文档中缺失或含糊、无法直接支撑实现**的规则；每条给出：缺口、为什么阻塞、需要谁补什么。

---
## G1 离线结算（最高优先，阻塞"回来有惊喜"核心钩子）
| 缺什么 | 现状 | 阻塞点 |
|---|---|---|
| 结算触发时机 | 文档仅写"离线收益"（`03` §2.1、`策划文档` A5），未定义触发点 | 是页面加载时、`visibilitychange` 回前台、还是固定间隔？直接影响实现位置与幂等 |
| 本地时钟不可信的有界化规则 | 无任何文档 | 无服务端时间权威，需明确：时钟回拨/前跳如何截断、上限多少、是否落"结算凭证"防重复 |
| 上限与衰减 | 甲说 8h/0.55、丙说 24h/0.6（见冲突 C1） | 参数未裁决 + 未定义超上限是否分段衰减 |
| 与战斗/驻军状态交互 | 未定义 | 离线期间若有未结束战斗/驻军相位，结算如何处理 |
| 产物形式 | `03` 提"离线报告卡"；`04` 2-A 列为 P0 | 报告卡数据结构、是否入存档、重复打开是否重复领取 |

## G2 操作幂等与防重复发奖
| 缺什么 | 现状 | 阻塞点 |
|---|---|---|
| 需幂等的操作清单 | 无 | 至少：研究（研究按钮重复点）、建造/升级、导入、恢复、重置、离线领取；缺清单无法写用例 |
| 幂等键与存储位置 | 无 | 本地无服务端 token，需定义本地幂等键（如操作 id + 时间窗）及其在存档中的字段（可能触发存档 v3） |
| 重复点击的判定期 | 无 | 现有 UI 用 `disabled` 兜底（如研究按钮 canAfford），但逻辑层无幂等记录 |

## G3 防作弊边界（须如实声明）
| 缺什么 | 现状 | 阻塞点 |
|---|---|---|
| 可接受边界声明 | 无 | 纯本地无法真正防篡改（改 localStorage/改时钟皆可）；需用户确认"允许的边界"（有界化+对拍自证，不承诺防作弊） |
| 时钟异常处理策略 | 无 | 回拨/前跳/跨时区/夏令时 |
| 存档完整性校验 | IE-001 有结构校验、无签名 | 是否需要本地校验和（非加密）以发现手改？需裁决 |

## G4 存档版本与快照策略
| 缺什么 | 现状 | 阻塞点 |
|---|---|---|
| v2→v3 触发条件与内容 | 现存 v2（含 sciences） | 若 G2 需新增字段（幂等键/离线凭证），必须定义 v3 迁移与回滚 |
| 快照/增量策略 | 当前"事件驱动 + 60s 兜底"（`math.js@614`） | 离线结算写入是否单独快照？与备份轮转/PRE 的交互顺序未定义 |
| 迁移失败回滚步骤 | IE-001 有保护模式，但无"演练过"记录 | 阶段 5 要求实际演练一次（需先有回滚开关设计） |

## G5 定时调度与离线推进
| 缺什么 | 现状 | 阻塞点 |
|---|---|---|
| 离线期间队列/建筑/驻军是否推进 | 无规则（竞品：训练队列离线照推、战斗不结算；`analysis-economy` §5） | 决定离线结算的输入面（资源速率是否含队列消耗） |
| tick 与离线的对齐 | `ui.js@977` 1s tick；无离线分段 | 长离线（24h=86400 tick）不可逐 tick 模拟 → 需闭式公式或分段积分，公式未定义 |
| 定时器节流/后台行为 | 无 | 移动端 WebView 后台暂停行为未定义（影响"在线净速率"取数） |
