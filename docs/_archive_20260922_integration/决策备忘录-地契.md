# 决策备忘录 · 「地契」怎么实现（R2=A 第二半的前置）

- 背景：你选了 **R2=A**（城镇升级改「资源 + 科技」门；上限改自身 LvMax）。上限那半已完成（切片 8b）。剩城镇门需要一个"资源"。
- 竞品事实（实证偏移见 `答复-R2-放置时代进度门.md`）：城镇三档 `村庄/小镇/城市` 需要 **地契 5 / 15 / 30**，科技前置 `0 / 450010城镇化 / 450012城市化`；地契来源**三路**（市场 `银两200→地契1`、交易所 `兽骨20→地契10`、宝箱 `+50`）＋战斗掉落（可选）。

## 方案对比
| 方案 | 做法 | 对齐度 | 改动面 | 风险 |
|---|---|---|---|---|
| **D1 复用金币（无新资源）** | 城镇升级耗「金币 + 科技点」；金币来自铸币厂（工人链）+市场兑换 → 完全非战斗可达 | 中（结构对齐，皮不同） | 小（`CFG.town` 加 cost + 城镇升级判定 + UI 显示） | 低 |
| **D4 金币 + 科技点双门（D1 变体）** | 同上，但明确"科技点门槛"作为第二层（如 城镇化/城市化 两个新科技节点） | 中高（资源门+科技门双层，最接近竞品） | 中（含 2 个新科技节点，切片 5 长阶梯可容纳） | 低 |
| **D2 新设「地契」资源** | 新增资源 `deed`（皮：地契/拓荒令），来源=市场兑换（金币→地契）+ 战斗掉落；城镇升级只耗地契 | **高**（语义与竞品一致） | 中（资源表+图标+UI+存档兼容检查） | 中（存档 res 新增 key：v2 校验只要求 copper/iron/coin 必需，新 key 不破坏校验；但需 UI 图标与初始值处理） |
| D3 战功 + 资源 | 城镇升级耗战功 | 低（半战斗门，违背 A 的初衷） | 小 | 低 |

## 若选 D2（新资源）需一并确认的点
1. **命名（皮）**：地契 / 拓荒令 / 领地凭证（你定）
2. **来源比例**：金币→地契 汇率（候选：100 金币→1 地契，市场日限沿用切片13 的每日次数）
3. **初始值**：新档给 0（首级城镇 Lv1→Lv2 需 5，即 ~500 金币）
4. **图标**：需在 `sprites.js` 加 1 个 32×32 像素图标（我可按现有风格画）
5. **存档**：`res.deed` 为新 key，迁移为"缺则补 0"（不强制必需，避免旧档被拒）
