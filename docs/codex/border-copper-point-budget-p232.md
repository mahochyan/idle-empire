# P232：首个铜脉采集点的5／10／30战经济预算

日期：2026-09-26。**结论：首胜授予1级铜点、只激活一个点、每60秒基础采2铜，可以作为下一批的状态与结算原型；单靠这笔点位收益，尚不足以定为首个可复刷边疆区域的正式价格。**本批仅做 [P229实付战斗数据](reports/data/p229-development-frontier.json) 的只读账本模型，没有改玩家代码、UI、总策划或存档；可复算公式与16流明细见 [P232模型JSON](reports/data/p232-border-copper-point-model.json)。现有100关仍是高难主线，区域线负责成长补给，二者奖励不能互相冒充。

**后续源码复核（P235）：**母本边疆点位并非首胜固定1级；`winMiddleWar`在每次胜利时按警戒奖励倍率加级，低警戒初期每胜+1级、上限500。见[母本结算复核](border-point-source-correction-p235.md)。因此本报告的“只首胜授1级”仅保留为我方保守候选的经济下界，不能称为母本对齐规则；模型数值本身不变。

## 事实、候选与模型边界

- 母本源 `560005` 铜矿山贼的静态 `Get=[[250005,1],[160004,400]]`，其中 `250005` 是采集点，`160004` 是铜钱。采集点表 `Get=[150006,2]` 指向铜；原始脚本 `autoCollect` 选定**一个**点位，每60000毫秒以点位等级×基础量采集，再经加成结算，见 `210(1)_unpacked/game_main.decrypted.js` 约字符位2392566及 [analysis-economy.md](../../analysis-economy.md) §2。**“首胜只给1级、复刷不再加级”是本批我方候选假设，不是母本通用首胜事实。**本批只核算采集点铜，不计母本静态铜钱400，也不把它直接移为我方铜钱：我方 `coin` 汇率、仓容、奖池和实付战后净额尚未同档定价。因此不能以铜点回本慢直接断定整场区域净收益为负。
- [P167](reports/data/p167-current-first-clear-campaign.json) 付款入口为18人口、零主线胜场，铜工3、铜库存57/上限800、食物4.9599，已有36兵，但合法阵位实际派出8盾卫＋13弓手。现行铜岗为1铜/人/秒，所以工人共3铜/秒＝180铜/分钟；1级铜点基础2铜/分钟在**满额激活、未满仓、无加成**时只相当于一个铜工的1/30、现有3铜工产速的1/90（约1.11%）。点位不是一次性发2铜，更不是+2铜/秒。
- [P229](development-frontier-candidate-p229.md) 的R1敌阵为步兵`[5,4]`＋弓手`[2]`。16个固定随机流都胜，损1–7人；战后合法把1名石工调到木岗，再走实际排队、付款和逐秒 `tick()`，16流均补回原阵。每战实际补费铜100–500（16流算术均值262.5）、粮300–1530（均值836.25）、木0–400；补兵81–380模拟在线秒（均值214.125），付款瞬间最低粮仅0.034。点位功能尚未实现，P229没有给任何存档凭空加铜。

## 仓容与现有工人改变了“回本”含义

P229每条R1首次补兵都证实当前3铜工的产量已覆盖铜付款：`3×补兵秒−实付铜`为正143–640；不计点位时，铜库存从57升到200–697。点位首次补兵窗口最多基础2–12铜，不是胜负或补兵可达性的关键。若**完全不再花铜且岗位保持不变**，用现有3铜/秒、800上限逐秒推算：60/120/180/240秒的4次点位脉冲各可实收2铜，245秒仓满；第1小时名义120铜，实际只入8铜，后续脉冲全溢出。此为仓满反例模型，未在游戏里运行新点位函数。

重复战斗会因训练付款重新腾出仓位，实际点位可收多少必须看付款与60秒脉冲的先后，不能从P229战后快照倒推。若机械地重复同一流和其第一次补兵耗时，原有铜工扣掉补费仍每次净增143–640铜；以57起算，约第2–6个补兵窗口就会触及800仓容。后续点位收入因此很可能低于表中的理想120铜/小时，具体损失需待真实连续挑战、仓容和离线实现验证。玩家切换去其它采集点时，铜点若非激活状态则这段时间收益为0。

## 下一实施批的价格护栏

1. **点位身份和发放**：首胜仅授1级铜点是我方适配候选；存档记录等级、当前激活点与60秒时钟。胜利结算一次性、保存失败回滚；败逃、重复回调和重复胜利不能多给首胜等级。复刷若另有奖励，应独立定价和记录名义/实入，不把母本铜钱400原样套入我方 `coin`。
2. **生产与人口**：采集点是持久定时来源，和3名铜工的岗位产率分账；不因获得点位增村民，也不关闭市场购契、聚落自然出生的零胜场保底。只激活一个点，未激活或等级0不产；满仓显示实际0入库，旧档默认0并保留原铜岗产速。在线与离线共用倒计时/封顶规则，测试采集点切换、刷新、离线重复领取和旧档迁移。
3. **经济与军粮**：R1的16流最低付款后粮0.034，尚无可接受的粮安全余量；从零木岗到木岗1人的真实调岗是补兵可达前提。每次复刷还要付木石粮、维持军队并耗真实活动时间；点位铜量不能替代这些费用。正式标价前至少用同一份实付完整档连续打5、10、30次，实际入库点位收益、铜钱奖励、仓容溢出、训练队列停工、粮最低值以及保存重载；再用无主线L19成绩的真实档检查区域是否真能支撑高难主线。

因此，本报告只给出**“首胜固定1级”保守候选的经济下界**，不是后续实施的既定奖励合同。P235已证母本低警戒期每次胜利都加级；若我方复刷也只给这一级点位而无另定材料/铜钱/其它回报，重复挑战没有铜点增量收入，表中的补兵铜账会越积越大。是否沿母本每胜加级、设置我方其它收益、调整点位产量或敌阵压力，必须以真实连续档与我方 `coin` 经济共同定价，不能从这张模型表拍板。单点激活与60秒定时采集的**后台状态语义**可独立实现。
