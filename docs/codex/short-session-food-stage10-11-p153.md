# P152/P153：四学者短时路线接续L10–L11（2026-09-26）

## 方法与边界

P152/P153沿用P151的四学者零胜场人口真实`save()`入口、当前P102战役函数、每600在线秒后离线28800秒的profile、固定战斗随机值0.5，以及石／煤／铜三种粮工调入来源×当前岗位／开发侧前置金属／开发侧前置粮食三条分支。P102只在`tools/verify`临时副本中插入真实`setPopAlloc()`岗位调动与L9胜后继续关卡的诊断代码，执行结束即删除临时副本。开发侧前置金属／粮食分支的L3+6地契仍是模拟奖励，不代表玩家逻辑。

**奖励口径补充（P155，2026-09-26）**：上述“当前岗位”仍只表示岗位分配分支。P102会在所有分支每场胜利后模拟注入`ceil(关卡ID/10)`张基础候选地契，前置金属／粮食分支在L3胜利时另加6张；当前`levels.js`关卡奖励没有地契字段。因此P151–P153接续战役不是现行奖励系统回放，也不是无地契奖励基线；它们的战后扩容、人口和战斗结果限于测试候选奖励条件。独立的无地契对照见[P139](live-deed-baseline-p139.md)。

P152在L9首败后用当前P102流程真实排队补兵、等待600在线秒并重试；胜后再补至目标编队，等待600在线秒（期间按profile触发离线结算），随后接战L10。P153在L10获胜后重复同一补兵与等待路径，接战L11。两批共9种来源／岗位组合；P153每条完整路线有9个28800秒离线窗，共81窗。

P153的81个离线窗均用真实`settleOffline()`完整推进，窗末粮食为3000。窗口触发在线计数为4800、5400、6000、6600、7200、7800、8400、9000、9600秒。三类来源与三条岗位分支的关卡和兵力结果完全相同。P151记录的前三种阶段（L1–L8、L9首败与恢复）在此延续：L9第一次失败，真实恢复后重试获胜；P152接出的L10也全部获胜。

固定流中的L10有40名敌军，探针计算的兵数加权攻击为300；L11为7名敌军、加权攻击28。该指标只用于描述本探针读出的编队，不等同完整胜率或玩家威胁评分。L10胜利耗掉13名青铜守卫，L11前的真实目标队列为补13名青铜守卫与1名猎人；一次600在线秒并触发一个8小时离线窗后，队列清空、粮食与金属回满仓，人口为19/19，编队恢复15／13／15。L11因此成为一个实际的战损恢复出口，但本记录没有继续挑战L12。

## 设计含义

在这条短时profile与固定随机流里，至少3粮工的岗位候选不仅跨过L4后的连续粮食窗口，也支撑了L9一次失败重试、L10首领胜利和L10战损后的L11恢复。它不意味着应把3粮工写成全局规则：短时路线的长期石／煤／铜机会成本、其它粮仓／编队、连续在线、其它随机战斗和经济／均衡／军事人口策略仍未对照。前置+6地契只是测试分支，不能用它证明奖励已经平衡或上线。

另一个需要进入难度曲线复核的发现是，当前固定流里L10为40名敌军／300加权攻击，紧接的L11降到7名／28加权攻击，L10虽造成13名青铜守卫战损，却能在下一次短时窗口后于L11满编获胜。这提供了“首领压力—恢复出口”的可达样本，同时显示L10到L11的敌压落差很大；单随机流不能替代多种子胜率与整段难度曲线审查。

这不构成P112完整短时战役、L12或全时代成长曲线通过。没有玩家运行代码、CFG、存档格式、奖励、UI、美术、Android或玩家`rts_save`变更。
