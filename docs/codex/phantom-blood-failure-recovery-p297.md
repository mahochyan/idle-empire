# P297 血剂失败流：付费补兵、复战与战剂购买

## 文档目标、代码现状、本次决定

《策划文档》要求发展副本持续供给母本式军力成长，100 关保留全科技后的陡峭主线。P296 从一份实付档证明了首份炽翼战剂市场购买，但相同档的 11 条连续战斗流有 3 条在光学拟态机警戒 2100 全损，停在 18 份圣兽血剂。若失败后无法通过经济和训练回到副本，这条长期供给链仍断。本批选其中种子 3，继续用真实岗位、逐秒生产、训练、编队、战斗和市场动作核算恢复成本；玩家运行配置、存档格式和 UI 美术均未改。

原有 `tests/progression/harness.js` 把 Node 主进程的同一个 `Math` 对象传给所有隔离存档：两个环境分别写 `Math.random` 后，前一环境及主进程都被后一环境覆盖。基线最小复现读到 `a=0.2, b=0.2, host=0.2`，使并列复战对照不可信。本批只在开发侧为每个 VM 提供继承标准数学函数的独立 `Math` 对象，并增加隔离回归测试。随后重跑 P296 两个探针及本批双分支，避免把串流结果写入策划结论。

## 失败到下一份战剂的实付链

输入仍为 [P295 实付终档](reports/data/p295-aegis-elixir-paid-save.json)，SHA-256 `5909b1e9fcab59140edb76bde9ce21736d387f4f0b73b384bf0076210d5b80d1`，其攻击／圣盾增益继承 P294/P295 各一次刻意有利稀有掉落，不能代表普通新档。连续 xorshift32 种子 3 的前 15 场材料战获胜，血剂 2→18；第 16 场战前警戒 2100、284 名出战兵，全损后血剂与警戒不增加。失败结算和存档保持可用。

以原出战阵型的 93 星际先遣兵、40 黄金重骑兵和 220 弓手为目标，先清空零兵编队，再通过真实 `setPopAlloc` 将 100 名村民留在粮食岗位、902 名轮转石／煤／铜／铁／钢岗位，逐秒 `tick()`，用 `train()` 排队、真实队列结算扣费并通过编队动作恢复原阵。训练配置费用合计为铜／铁／钢各 744000、粮 46600、金属金 4000、石 4400、木 17600；3693 个**模拟在线生产秒**后 353 名出战兵恢复，过程中最低粮食约 384085，未断粮。原岗位配置随后恢复。该时间不计玩家操作与战斗动画，开发侧测试禁用了驻军自动推进，不能当现实玩家恢复时长。

从同一付费重建档、同一战斗随机状态作隔离对照：**不使用净化剂**在警戒 2100 复战胜，353→304 人，血剂 18→20、警戒→2200；**实扣已有一剂**的旁支在警戒 2000 也胜，余 305 人。对这一个固定流，净化剂仅多保留 1 名兵，本批选不消耗的一支继续，以留给后续更难战斗；这不是其它流的普遍最优策略。[复战后存档](reports/data/p297-phantom-blood-retry-save.json)可独立重载，SHA-256 `9c631436bf6d7d7876e6e023ecdf8b198f309345bd9cfa3f0dc8edfb6dcd2ef9`。

从 20 份血剂继续，以独立固定市场种子 291 调用现行 `offlineAdvanceSec(60,1)` 共 39 次、2340 个倍率 1 的模拟生产秒；见到炽翼战剂货位后真实 `buyMarketSpecial('emberElixir')`，血剂 20→0、战剂 0→1、货位扣 1。终档余 304 出战兵、1 剂净化剂、43 高能核心不变，[逐步账本](reports/data/p297-phantom-blood-recovery-report.json)、[终档](reports/data/p297-phantom-blood-recovery-save.json)及[复算脚本](../../tools/verify/probe-phantom-blood-recovery-p297.js)可核；终档 SHA-256 `7d13a2160caa31695917ec8100ed9a5d534ce503e6bd2cd6aeba7f3926aab89e`，两次复算一致。2340 秒是选择的快货位流，与 P296 所算约 8.90 小时的理想首格期望不同；不能写成典型市场等待。

恢复虽可付款，资源缓冲很薄：复战后煤约 327.5、铁 1262、钢 659；市场推进后也只回到煤约 2667.5、铁 1262、钢 659。下一次大规模补训必须再筹上游煤、石及三金属，不能从本批推断连续无间断刷取、三份炽翼战剂可持续兑换圣盾秘剂，或警戒 5000 高能核心与第 7–20 阶已经闭合。
