# P63 边贸行图纸刷新与核能前容量边界（2026-09-24）

文档目标是按工作区《放置时代》的成长和难度骨架完成我方游戏，早中段用机巧／工业主题，后段用神魔西幻主题，原创玩法后置。P62代码现状是边贸行30级后图纸常驻，兽心足够便能立即连兑；这与母本的上架概率不符。本批只收紧这条图纸来源，保留已验证的早期兽骨→勋章稳定入口，不把其它尚未接入的交易品假装已实现。

## 母本证据与本批决定

解包主逻辑 `deob_main.js` 的 `refreshResource`（约偏移1324038）每轮按当前交易所等级，从可用商品的 `Rate` 加权抽取 `min(14, floor(Lv/10)+8)` 个商品位，重复抽中增加该商品上架数；每次重置商品库存。实体表290000为1000毫秒一计时、1200次一轮（20分钟）、初始商品位8；交易所初始刷新次数5、上限5，手动刷新扣1次，倒计时结束时先恢复刷新次数，次数已满才自动刷新。Lv30的27种可选商品总权重445，290084兽心→卷轴权重10，11个商品位中任一位抽中的概率`10/445`，一轮至少一份约`1-(435/445)^11=22.12%`，期望每轮约0.247份。Rate10不是兑换失败率：母本`exchange`已上架且材料足够时直接扣费给物。

母本每次抽中商品还按等级尝试将费用品质设为80%、50%、10%（后一步可覆盖前一步）；30级阈值依次为35%、7%、4‰。290084在不按交易所等级涨价的特殊商品ID区间，因此每份默认兽心200，品质折扣后分别160、100、20。当前项目只投影290084：根据源表逐等级累计总权重抽图纸份数，不生成其它未实现的商品；兽骨兑勋章保留常驻，这是我方前期勋章与军备研究的已验证桥梁，**不称作母本完整交易所复刻**。20分钟按游戏在线秒推进，离线结算不补刷新；刷新次数、倒计时、上架数和品质都持久化。战斗进行期间在线秒仍推进倒计时。

实体表320004「知识上限」属于320000「核源星阵」的属性，源码`getPowerPosValue`从军队的`PowerPosList`已开放槽汇总。其升级材料170021／170022／170023均来自「星域异兽」，而450123星域异兽以450023核能时代为前置、需知识2亿与勋章100万。它不能提供核能前知识1亿的起始仓容，不应把它当作P61容量缺口的预支倍率。

## 代码、存档与实付

`CFG.beastExchange`增加源表权重阶梯、商品位、1200秒与5次刷新配置；`S.beastExchange`增加`heartOffers`、`heartQuality`、`refreshClock`、`refreshCharges`。动作函数先验等级、上架库存、兽心和图纸容量，交易消耗实际上架份数；手动刷新保存失败则回滚库存和次数，交易失败回滚全部资源与库存。`tick()`在线推进刷新；货品卡显示上架份数、实际兽心价格、刷新次数和倒计时。名称仍为「兽心／机巧拓仓图纸Ⅰ」，后段神祇术语不改。

`rts_save`版本v27→v28。v0–v27只在独立候选数据上补新刷新字段，旧兽心、图纸、已用次数、交易所等级与进度均保留；原文保护副本先于覆盖主档。v28缺失、越界、未知品质和未来v29进入只读保护，合法0不会被缺省吞掉。关闭新入口不得删除旧字段。旧v27代码不认识v28，回退前须先导出当前主档和`rts_save_premigration`，在对应版本验证恢复；不能直接用旧代码写回新档。

从P62同一未兑换实付v27档（郊野警戒值4000、兽骨138283、兽心1025、知识仓容5001920）加载到v28，逐级2610笔兽骨兑换仍实付119480骨、增加238960勋章，等级1→30。开发探针使用固定xorshift种子9，按真实刷新次数与`tick()`恢复路径获取5份图纸：手动刷新25次，额外推进24000在线秒（6.67小时）；上架并购得的5份品质依次80、100、100、100、100，实付兽心960，剩65。使用5份后知识仓容5001920→5252016，最终v28重载保留已用次数与库存。探针即时执行动作和战斗回调，种子9是单路线，不代表典型抽卡运气或真人操作时长。

本批只校正一条取得路径，核能知识1亿和勋章80万仍未同档实付。P61条件仓容上界44542080即使乘5张图纸的1.05也只有46769184；按该条件上界仍需至少125张图纸才过1亿，且当前固定编队在郊野警戒值4000附近有战力墙。50小时、多策略、完整十时代和母本交易所其它商品尚未验收。
