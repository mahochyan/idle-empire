# P131：工坊产出成长与粮食—军需接力

日期：2026-09-25。工作目标：核对母本工坊产出加成在我方映射实体上的成长率，并以真实存档重算调岗后的粮食和金属净产。严格避开UI与美术文件。

## 母本依据与实现

analysis-economy.md §3记录母本workShop来源260001–260013对应的工人加成均为每级+10%，即岗位产出乘以1 + 工坊等级×0.1。P129映射的11个我方workShop职能节点中，煤井、矿井、冶炼、贵金属/钢冶炼、铸币和学院已使用每级10%；只有伐木场、采石场、农田仍设基础加成0.20、每级0.25。它们在Lv1/Lv5/Lv10的有效加成为45%/145%/270%，母本同级为10%/50%/100%。

P131将上述三项设为基础0、每级0.1。workshop_buff_growth.js校验11项映射源ID均为base0/perLevel0.1，并通过真实buildingBuff和prodRate检查伐木、采石、农田在Lv1/Lv10的实际倍率，2/2通过。木、石基础产率保持3和2；食物仍走既有R5对齐规则2.25，并未改成母本原始5；村民口粮、军队维护、仓储容量及资源初建费用均未改。本次只对齐工坊乘区。

## 人口—粮食—军需复算

用P72付费成熟快照，初始126人口、203名军队、农田Lv1，真实重载后调用市场、农田升级、调岗、逐秒tick和隔离存档重载。P73旧倍率下的26粮工/30石/29煤/14铁/27钢配置在新+10%曲线下不能维持粮食；在该档固定126人口和203军队时，需改变岗位分配。

新配置保留43粮工，安排30石工、23煤工、12铁工、18钢工。农田升至Lv5后真实运行1000模拟在线秒，五项净速率为石18、粮6.96835、煤4.5、铁6、钢36/秒；整个农田升级过程最低粮食库存10608，人口126与军队203保持。由于资源岗位占人口，钢净产从P73旧倍率结果54/秒下降18/秒。这个结果说明，按母本降低粮食工坊的单级增益以后，当前基础食物产率和军粮规则需要更多村民投向粮食；要同时保住原钢产，需继续验证住房扩容或军粮/基础产率适配。P131不通过额外送人口、资源、胜场或改军粮参数绕过成本。

P131零战斗蒸汽路线在284068模拟在线秒、26人口时训练首名装甲兵；钢链上游转正检查点133110秒的库存粮为424.533，低储备风险仍然存在。P130路线281330秒同时使用了较高的早期工坊加成，且岗位/市场动作不同；两者不是单变量对照。另一个早期新档路线在5341秒到18人口、7804秒到22人口、12204秒到26人口。路线时间只用于同一模拟口径的路径复核，不是实际玩家时长或四策略验收。
