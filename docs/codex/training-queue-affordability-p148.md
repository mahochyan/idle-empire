# P148：训练队列建立与资源支付边界（2026-09-26）

## 方法

分别把P145第4关胜后真实隔离存档载入开发harness，测试步兵、猎人和青铜刀盾兵。每种情景只在harness里清空测试队列、移出该兵种现有兵池／远征编队，并把其当前CFG训练费用涉及的资源设为0；随后调用真实`train()`、`processQueue()`和本地harness存档。最后给回恰好1名该兵种的费用，再调用真实`processQueue()`验证实际产出与扣款。

这是一项队列/生产边界测试，不是战役路线复跑。清队列、移出测试兵和改库存只发生在独立harness；没有读取或写入玩家浏览器存档。

## 设计含义与边界

P147的“材料库存改写发生在已建立队列之后”不再是队列创建的未知项：当前实现的`train()`先写入待训数量，不预扣或校验单兵资源；费用在真实生产时扣除，零库存只会令生产暂停。因此“资源是否足以排队”和“资源能否把队列转成战力”是两个不同检查点。这个结论只覆盖上述三种基础兵、已满足建筑/科技门槛、队列空间可用的19人口战后存档；它不代表无资源也能获得士兵、不覆盖被锁兵种/满队列/满兵种上限，也没有完成8小时粮账或多策略战役。

人口增长路线仍要单独验证自然出生、住房/粮食与扩张资源的接续。排队成功不是额外人口，也不能替代实际生产成本；本探针不调整村民出生率、首通奖励或任何玩家数值。

验证：`node --check tools/verify/probe-training-queue-affordability-p148.js`退出0；`node tools/verify/probe-training-queue-affordability-p148.js`退出0。三类兵种均断言入队后资源不变且已写入harness存档、零资源生产暂停、精确补费后兵池/队列/费用存档一致。逐情景结果与输入SHA见[P148原始数据](reports/data/p148-training-queue-affordability.json)。
