# 人口供给与关卡成长的接口方案 P124

日期：2026-09-25  
策划文档版本：v2.51  
状态：P124历史设计建议；当时未确认实现

> 本行记录P124当时的状态。P165已将下述唯一早期候选（第3关首胜+6地契）接入本地结算供复测；全关卡奖励数值和多策略成长曲线仍未确认，见[P165复查](population-first-clear-reward-p165.md)。

## 结论

玩家感到“要打关才能增加村民”，与当前规则需要拆开看：当前自然出生仍会在**有粮、住房有空位、在线推进**时发生；普通关卡胜利不会直接增加居民，也不发地契。人口进度更容易被住房容量／地契续供卡住，打关给到的基础资源和内容进度则让玩家把两条成长线感知成一件事。

建议保留“自然出生是劳动力保底、市场／生产支持无胜场扩容、关卡首通只加速后续住房”的三层骨干。首通奖励若采纳，应发到现有地契资源，不直接造村民、不回填当前战斗，也不能替代市场。早期可继续把“第3关首胜额外+6地契”当作**一个容量档的敏感度候选**；目前证据只说明它能在特定18人口存档中买到+1住房容量，没有证明能改善L6、L7–L10或整体成长速度。

母本的直接参照是**成长职责分层**，不是复制“关卡送人口”：母本把住房／人口政策、资源与科技产能、区域挑战和各自的 `Get` 奖励分别放在不同进度轨上；已审计内容没有普通关卡通用首通奖励表。我方若增加首通拓居奖励，属于服务我方100关章节结构的适配方案，不能记成母本机制。

## 推荐骨干与数值处理

### 1. 保留三条职责不同的成长线

| 成长线 | 负责什么 | 不替代什么 |
|---|---|---|
| 自然出生 | 在已有容量与正粮条件下提供基础劳动力；不要求玩家先赢关。 | 不自动增加住房容量，不保证人口岗位与资源已配好。 |
| 市场／生产 | 以可持续的经济方式补地契，使零战斗路线可以继续扩容。 | 不保证每一条军事路线都能快速到达，也不抹去交易、仓容和工人机会成本。 |
| 关卡首胜候选 | 在战后补一段住房资源，缩短下一次容量购买等待；成为可选加速支线。 | 不直接生人、不为刚结束的战斗补战力、不重复领取、不替代稳定市场供给。 |

### 2. 早期只保留一个可复测候选，不定全曲线

- **候选里程碑：**第3关首次胜利后发放额外6地契。给玩家显示的名称候选为**“拓居令”**，强调边境开拓与聚落建设；现有内部资源键仍为 `deed`。不使用神祇、西幻称谓，也不在本设计批次改UI显示。
- **候选作用：**在P102的特定路线中，6地契与已有余额合计后足以支付一次9地契村庄扩建；之后仍需有粮、在线等10秒，实际人口才从18到19。该值只作为“战后买到一个容量”的压力测试点，不作为确认奖励。
- **发放时点：**若将来采纳，必须等第3关胜利结算后才到账；该战和更早的关卡不能使用奖励。复战不得重复领取。
- **不外推：**第4–10关和后续章节暂不填具体奖励。应先从每个时代的岗位预算和下一笔聚落升级成本反推，再用重经济、均衡、军事和短时上线路线逐点校准；不照搬旧静态模型中的“100关累计600地契”。

容量里程碑应由实际工作包反推，而非按关卡编号给人口定额。当前可暂用“开局4容量、基础铜链工作位8、我方铁与铸币并行的14容量”为验证检查点；其中14只是我方现有配方下的候选，母本铜／铁原料拓扑不同，且军队维护尚未合账，不能直接作为已定时代门。每个章节奖励的预算以加速到**下一档计划容量**为单次目标，不替整时代人口供给兜底；更大的劳动力台阶仍由产业、研究、市场与自然出生共同承担，避免胜场奖形成指数式滚雪球。

### 3. 奖励预算按“目标容量”而非“人头”计算

后续逐章数值表至少写明：

1. 该检查点之前经济路线能否不打关取得下一笔地契；
2. 目标岗位包需要多少**实际人口**、住房容量、空闲工人和正净粮；
3. 首胜奖能否只加速一次当前计划的聚落扩建，购买后还需要多少自然出生和岗位准备时间；
4. 新增工人转岗后，木／石／金属生产、军粮、招募队列和下一战军力如何变化；
5. 普通关与专项区域的首胜、复战收益及仓容截断是否仍各司其职。

首胜奖使用固定关卡／章节表，不按玩家当前余额动态补齐，也不因战败、重复战或读档重领而增长。若日后需要按存档状态补足费用，那将改变奖励规则与防重复语义，应单独审议，不能隐入这一方案。

## 验收顺序

1. **先校正体验解释：**面板／提示要能区分“人口增长条件”“当前住房余量”“下一档地契缺口”；这项界面工作留给负责UI美化的 agent，本方案不改UI文件。
2. **确认经济保底：**零胜场路线能到达开局、铜链、铁／铸币候选容量检查点，记录真实地契收入、市场操作、仓容、粮食和岗位净率。
3. **测早期战后容量候选：**同一存档分出无奖与第3关+6支线；严格在首胜后发奖，验证扩建一次、出生一次、转岗生产，并跑到能比较的下一道战力墙。P102／P123已表明只看胜负或延长等待不足以定案。
4. **再测多策略共同节点：**重经济、均衡、军事、短时上线／离线使用同一配置与检查点，不跨档拼接。每个点同时报告地契、容量、实际人口、岗位净流、军粮、存活兵、队列、胜败、损兵与补回时间。
5. **最后才填写后续章节奖表：**不以简单每关发奖或每章固定倍增为默认方案；先让工资／产能／战力资源墙可解释，再确定哪些章末节点需要住房加速。

若实现首通记录，必须确认现有 `S.defeated` 是否足以保证一次性结算；不能预设它同时代表逐关领奖账本。奖励需要保存、旧档默认、迁移、重复结算、战后保存失败及回退一起验证。此处尚无新字段决策，不对旧档兼容作通过声明。
