# P281 试炼守卫出手人数与追加伤害量纲复查

> 历史规则快照：P283随后接入守卫首次防御被动，旧第5阶3/11胜已变为当前规则0/11；当前实付军备接力见[P283报告](awakening-guard-passives-nano-bridge-p283.md)。

## 文档目标、代码现状、本次决定

《策划文档》把圣域试炼列为《放置时代》式发展线，第100关另作全科技后的高难主线。P280已接入370009星际兵前两项觉醒技和540091简单守卫追加伤害，但P279已付款的155星际兵档在第6阶11个种子仍全败，且守卫余39911–45904 HP。本批只校正圣域试炼守卫的本场战斗映射，不改关卡、科技、训练、掉落、UI或并行美术。

母本540091的每名守卫有自己的生命和攻击；当前我方把整群守卫合为一个HP条及独立`attackMass`。P280代码在守卫失血后仍以进场546人出手。现仅给觉醒试炼敌方战斗体加`attackMassFallsWithHp`标记，共用的`combatAttackMass()`按`ceil(进场出手人数 × 当前HP ÷ 进场最大HP)`折减；普通遗迹／神祇单体Boss仍保持固定出手规模。护盾先吸收伤害，不损出手人数；死亡后出手为0。这是聚合兵团的本地近似，不声称精确追踪母本每名守卫的伤势。

另一个量纲偏差是P275把母本守卫攻击约÷10映到我方，玩家单兵生命则约÷100（例如宇航兵400→星际先遣兵4）；P280直接用本地守卫攻击的30%作真伤，使它相对本地士兵生命放大约10倍。本批保留母本「每名守卫攻击时30%概率、追加自身30%攻击」的触发与源比例，并在**落到我方生命口径**时再乘0.1。这个0.1是两套既有属性缩放比，不是把源技能改写成3%。技能只改变本场HP，存档内不加新字段。

曾在隔离试验中让合并守卫逐兵抽不同目标、再分团结算。未作量纲换算时，P275已付款首阶档的连续路线在第2阶停住；换算后仍使P277第5阶已付款装备档11种子全败。该目标分配试验**已从玩家运行代码撤回**；当前守卫仍按原战斗模型一次选一团。实验数据保留为后续设计证据，不能作为当前规则的战果。
