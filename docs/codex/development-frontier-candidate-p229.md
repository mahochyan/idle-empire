## 母本职责与我方生产接缝

母本实体表 `210(1)_unpacked/_analysis/entities_table.json` 中，边疆铜矿山贼 `560005` 是 `middleWar`，基础属性150/22/8、人数档`[9,12,15]`，胜利配置`Get=[[250005,1],[160004,400]]`；`250005` 是 `collect` 铜矿点，`collect:Get=[150006,2]`。铁矿山贼 `560006` 同理给铁矿点 `250006`，其`collect:Get=[150007,1]`。进一步复核原始 `210(1)_unpacked/game_main.decrypted.js` 约字符位2392566：`autoCollect`以`setInterval(...,0xea60)`即60000毫秒执行，按`AutoInfo`当前**选中的一个点位**、`CollectLv[点位]×collect表Get[1]`为基础量，再经过科技等加成后入库；取消选择将ID置0。这说明是持久点位等级带来的定时采集，**不是当场给铜/铁，也不是所有已占点位每秒自动生产**。母本实际可选门、复刷时点位等级变化、满仓及离线结算仍需另行核验。母本外域 `570001` 枫林村庄是 `bigWar`，有 `570005` 民兵军阵和技能，`Get` 静态为地契3、勋章5；这些也不是我方价格。核对见 [母本经济分析](../../analysis-economy.md) §2、[母本全战斗账本](full-combat-reference-ledger.md) §3–4 与 [P117](stage-mother-map-p117.md)。

我方当前 `config.js` 的铜岗基础产率1/人/秒、铁岗0.5/人/秒；`math.js:prodRate()` 在岗位解锁、人数、建筑、电力等条件下计算，`productionSecond()` 检查金属配方原料与仓容，在线 `tick()` 和逐秒 `offlineAdvanceSec()` 都调用它。P167早期实付档有铜工3、铜57、铜仓容800，当前一秒候选库存升到60；P184战前档也有铜工3、铜703，铜仓容800。若按母本职责适配，点位应是**独立于村民岗位的持久、可选定时采集源**：保存点位等级、当前激活点和采集秒钟，60秒到期按待定产量入库，检查同一 `resCap()`，在线与离线推进一致；当前铜工0时岗位产率为0，但已激活点位仍可按其单独规则采集。母本铜点的静态基础量是每级每次2铜，**绝非+2铜/秒**；我方是否照用60秒和2铜、是否消耗石煤，以及与岗位、仓容的经济平衡，均需正式定价和实付验证。不能把点位暗塞进 `reward.copper` 或直接乘进 `prodRate()`，否则会丢掉选点/60秒语义。

## 最小可实施内容规格与上线边界

1. **边疆铜脉哨站**：拟在铜研究/采铜岗位已经可用的早期开放（P167是现成可付入口，不证明更早入口）；战斗先取R1。胜利应授予独立的铜脉点位归属或等级记录。若按母本定时采集结构实施，还需激活点位选择和60秒累积时钟；同一条逐秒推进路径用于在线与离线，发放时走 `resCap()` 并记录名义/实入量。具体我方每次产量、是否消耗原料、重复战是否升级点位、同种点上限均未定价。无点/未激活时不产点位资源；铜工为0不能让原铜岗位凭空产出；满仓时不得以奖励显示掩盖实际0入库。败局/逃跑不能得点，重复回调不能重领。早期保留市场购契、聚落自然出生的零胜场人口保底，不把矿点或胜利变成人口硬门。
2. **外域军屯村寨**：战斗可先取V1，地契/战备勋章应作为该区域可重复回报职责，不能照抄母本3/5或把打赢直接转成村民。应按当前仓容、补兵账与研究付款定数，再验证首次和重复胜利、满仓、败逃的实入。V2可为后续等级。开放门不能偷偷设为主线L19；需要一份尚未过L19但已靠区域成长付出相近阵容的真实完整档。
3. **代码接入**：当前 `specialEncounterConfig()` / `materialDomainEncounter()` 假设材料副本只有一个主材料、单类敌组与警戒值，普通 `CFG.enemies` 胜利又会写主线`S.defeated`。需要新增区域键与多兵种解析/独立奖励结算，保留共用战斗回合和战损回写。持久状态至少包含区域进度、采集点归属/等级、激活点ID、60秒计时、重复挑战计数或警戒值；同步覆盖`SAVE_VERSION`、序列化、验证、迁移、默认值、加载、保护副本、结算失败回滚。定时采集应从共用的逐秒推进接入在线 `tick()` 与离线 `offlineAdvanceSec()`，与 `productionSecond()` 使用同一库存上限/舍入语义而不改坏既有岗位产率；不能只给UI文案或一次性`S.res.copper`。驻军仍按现有独立结算，不让区域状态串入驻军奖励。

**本轮可以开始做后端最小切片，但不能安全上线首个边疆区域。** 缺口是矿点的真实结算与持久状态字段、我方产量/原料/点位上限定价、无L19的村寨入口档、连续复刷补兵/粮食、离线与仓容、真实浏览器/Android保存回调。母本的60秒选点采集已由源脚本核实，却不能自动证明我方应照抄收益量；这些应在下一实现任务逐项验收，P229只给战斗原型和接缝证据。
