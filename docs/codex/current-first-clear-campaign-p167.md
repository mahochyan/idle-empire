# P167：拓居令从住房到补兵的同源战役复查（2026-09-26）

## 文档目标、代码现状与本次决定

P124要求把自然出生、市场扩容和战后地契加速分轨，再验证新增居民能否通过岗位、军粮和真实训练成为下一关战力。当前代码只在第3关首次胜利发放6张“拓居令（地契）”；其它关卡没有通用地契奖励。P166证明固定卖石策略下18→20住房时钟缩短，但没有补兵和后续胜负结果。本批保留现行+6，不调整关卡敌压或新奖励数值，以同源战役对照核实它在四种岗位安排下的实际作用。

## 方法

[P167探针](../../tools/verify/probe-current-first-clear-campaign-p167.js)复用P166从真实新档取得的18/18、0地契、0胜场战前序列化存档和真实DOM／战斗计时适配。军备入口tick为5815，拥有15步兵、13猎人、8青铜刀盾兵；实际出战数另按编队快照记录。每对分支共用这份存档；控制组只在隔离VM中关掉第3关的`firstClearReward`，双方都不运行P102历史探针的手工地契注入。L1–L3调用真实编队、`openBattle()`、回调、结算，并逐关断言胜负、战损、非地契资源、tick和L3补训目标相同；L3原生结算后地契为6／0。

两组都在L1／L2胜后等待10个在线tick秒；从L3起每场胜后真实排队补至持有目标15步兵／13猎人／15刀盾兵（含预备池），推进10＋600在线tick秒后开下一关，首次失败即停，最多尝试至L10。等待中每秒调用真实`tick()`，缺钱且石料至少1100时按每笔1000石通过市场出售，保留100石，再买当档缺少的地契、扩村并等待自然出生。第19／20名居民在每对分支中按相同的两岗策略上木／粮岗位：木木、木粮、粮木、粮粮。战斗随机流使用5个固定种子1、2、3、42、12345；每关开始按种子和关号重新初始化同一xorshift32流，保证有奖／无奖分支的该关随机输入一致。它是受控样本，不是玩家随机分布或胜率。战斗回调墙钟时间不计入在线tick秒，未模拟驻军或离线。

## 结果

共20对路线、40条真实战役／市场／队列回放。所有分支都实际到20/20人口；有奖支比同策略无奖支早528–556模拟在线秒到19人，早327–447秒到20人。实际销售、逐场库存、队列暂停原因、战损、出生、岗位和最终`save()`／重载快照见[原始数据](reports/data/p167-current-first-clear-campaign.json)。

| 新居民岗位 | 5种子有奖与无奖的首次战败关 | 可观察差异 |
|---|---|---|
| 木／木 | 5对均相同：L6、L7或L8 | 住房较快；未增加本组胜场 |
| 木／粮 | 5对均相同：4对L8、1对L7 | 岗位组合比木木在本组更能承接战损，但奖励本身未改变首败关 |
| 粮／木 | 5对均相同：4对L8、1对L7 | 与木粮同样未产生配对胜场差 |
| 粮／粮 | 4对同在L8；种子1有奖支首败L9、无奖支首败L7 | 唯一一对出现战役推进收益；有奖支多胜L7和L8 |

粮粮策略在L4战前，有奖支**拥有**12–13名青铜刀盾兵，对照为8–9名；受当时单个前排格每团最多10名限制，实际入场分别为10名和8–9名。种子1在L7战前，有奖支实际入场15刀盾兵／13猎人，无奖支15刀盾兵／9猎人；两支各有15名步兵留在预备池。前者胜L7并继续胜L8，L9首次失败，后者败于L7。提前出生的粮工、真实训练完成时间和较少的前场战损形成连锁效果；不能把其中任何一项单独当作胜负原因。木木策略更早补足猎人木料，但有些种子在有奖支拥有较少刀盾兵，说明“加快人口”不是自动加强军力。

**编队口径复查：**此前逐场`beforeArmy`统计拥有量（兵池＋编队），不能当成入场量。第5关胜后虽开放第二个前排格，P167的固定编队操作仍先铺青铜刀盾兵；40条L6战前记录拥有37–43名士兵，实际只入场22–28名，步兵入场均为0。胜负结果来自真实战斗，仍有效；但这组胜负只代表“刀盾优先”的编队策略，不能据此推断混编或升级兵种也过不了同一关。

全部20对路线都没进入L10实战，现行L3+6不能证明第一章章末可达。所有路线在此入口起的粮食最低值只约1.96–4.96，贴近耗尽，不能据“未到0”宣称军粮宽裕；石料最低值为100–102，市场交易与步兵／猎人训练确实共用石料，原始数据记录两者的时间顺序。P167未测试失败后再次训练、其它兵种和科研解锁，也未校准L10定位或多策略时代曲线。下一数值决策应把粮／木岗位预算、实际出战编队、L7–L9敌压和兵种质量一起验，而非直接提高出生倍率或铺满后续关卡奖励表。
