## 设计缺口与下一步验证（非新增玩法裁决）

1. **建立青铜/铁器各一条闭环账本**：前时代材料与知识仓容 → 450209/450211 式研究 → 招募所需粮/铜/铁 → 基础装备的 470xxx 研究与制造费 → 我方练兵/营地容量 → 首次挑战与重复刷取 → 战损补兵、材料回流。区分母本配置和我方选定价格；不能只增一个单位名称。
2. **给区域门和奖励做专项取证**：追母本郊外→边疆入口函数、560005/6 的 `Get`/`Rate`/采集点兑现、品质与杀戮值应用、首通和复刷；然后再定我方青铜/铁器面对的区域与奖励。当前没有证据支持“青铜十关、铁器十关”或任何固定胜率，不写阶段关数/成功率。
3. **先修可信战损再标定难度**：保持 `S` 中士兵人数守恒，把人数、单兵血量、临时盾与恢复分开；两条战斗入口都要检验。随后以真实函数回放产兵时间、每场有效伤害、回合、战损、补兵用时和单位时间材料收益，至少覆盖普通敌、Boss、远征、驻军及资源不够的情形。避免只看 HP/ATK 基表断言难易。
4. **研究门要落在动作函数**：营地时代升级和兵种前置都需验证真实动作入口；同时保留旧档已解锁单位、阵容和训练队列，不可为换时代结构静默裁剪。新增时代、装备、区域字段时按 `rts_save` 的候选解析、备份、迁移、序列化和失败保护链逐项验收。
