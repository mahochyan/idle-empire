# 首个小镇容量门的科研岗位敏感度（P104，2026-09-25）

- 对应权威设计：[《策划文档.md》§8.4、§8.9](../../策划文档.md)
- 探针：[新档人口探针](../../tools/verify/probe-population-early-18.js)，使用真实配置、生产、研究、市场、扩建和在线tick函数。
- 范围：只比较市场完工后、城镇化研究前的临时学者岗位数；不改玩家运行代码、人口/资源配置、奖励或存档。

## 对照方法

各路线均从相同新档开始，初始30地契升村庄到8容量；同样用基础采集、探矿/采煤/冶铜/木仓研究和建造打开市场。市场均在模拟在线t=500秒完工。随后对照在城镇化研究前把科研岗位从2人临时调到3–7人，其他空闲岗位相应从木工或石工转出；研究完成后各路线都恢复为木3、石2、粮1、学者2的同一分工，再使用相同的购契、扩镇、人口填充及后续岗位顺序。没有胜场、资源注入或铸币；测试VM关闭随机驻军。游戏秒不是现实耗时。

探针参数化新增了短时科研冲刺选项。首轮7人路线曾因探针岗位分配计算错误而退出码1；修正木/石工人数合计后，最终2–7人矩阵均退出码0。该失败是开发探针输入错误，不是游戏函数失败；修正后的7人结果已在表中列出。

## 设计结论与边界

1. 在这个零胜场早期样本里，住房容量从8升至10后，基础+2人／10秒足以在一个出生tick内填满新增的两个位置；自然出生不是这段主要等待。
2. 市场t=500开放后，知识与资源生产同时受8名村民分配限制。把研究岗位短时提高到4人，较原路线更早开小镇，连带提前后续人口与岗位预算；继续加学者则逐渐挤压交易所需的木/石生产。
3. 当前可用的调速方向是岗位节奏与科技门安排：让研究冲刺和购契生产分段接力。没有证据支持提高基础出生倍率、要求打关，或将4人永久写成硬性人口配置。
4. 这是同一脚本、同一基础市场时点下的岗位敏感度，不是重经济/均衡/军事/短时上线四策略对照，也不是母本同策略回放。研究岗位数只在2–7的离散范围测试，后续仍需考虑初次战斗训练、军粮、低操作与离线条件。

最终验证命令为`node --check tools/verify/probe-population-early-18.js`与该探针默认模式及`--research-workers=3`至`=7`六条路线，均退出码0；默认路线仍为5096秒到18人口。未运行浏览器/Android，未写玩家存档。
