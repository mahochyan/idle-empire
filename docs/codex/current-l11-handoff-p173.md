# P173：第10关终档到第二章前段的兵力承接（2026-09-26）

## 同源口径

[P173探针](../../tools/verify/probe-current-l11-handoff-p173.js)沿[P171实付路线](paid-regiment-capacity-bridge-p171.md)重新取得四个第10关胜利终档：固定随机流种子1／42，各有当前第3关首胜`+6拓居令`和隔离VM无奖对照，均采用粮／粮岗位。每支先用真实`save()`写入`rts_save`并重载，再从**同一个序列化L10档**分叉：一线以战后残兵立即打L11；另一线调用真实`train()`排队，在在线`tick()`中按队列生产补至拥有15青铜刀盾兵／15民兵／13游侠，之后打L11。胜利分支每关重载结算档，探索性地不再等待或补兵，连续挑战L12–L16或直到首次败北。所有战斗通过实际选关、编队、开战、回调和结算函数；仅随机数使用与P171相同的关卡固定流。没有资源注入、离线推进、驻军、玩家文件或UI改动。

四支L10胜利档在重载后木4800／石3200／粮3000均达到仓容上限，但人口与兵力不同：当前奖励支人口20／容量20，无奖支19／19；种子1均拥有青铜6／民兵0／游侠13，前排第二格确实空缺；种子42均拥有青铜9／民兵7／游侠11。L10结算后的**存档编队已经按战损回写**，不是战前15／15／13；探针出战前再次调用真实清编、入编动作，并单独记录拥有与实际入场。

种子1的真实补训为9青铜、15民兵；按实际出队人数和运行时单兵成本核算的训练应扣额合计木1200、石600、粮3600、铜900。种子42补训6青铜、8民兵、2游侠，应扣额合计木880、石400、粮2380、铜600。`train()`排队当下不扣资源，真实扣费由`processQueue()`产出时执行；探针断言产出数等于请求数，但**未独立从每秒生产净流中拆出逐笔实扣**。种子1起点粮虽满仓3000，补训应扣粮3600，必须依赖在线生产；其青铜队列因资源不足显示暂停分别86／137个tick、民兵队列34／56个tick。上述“最低粮”是**每次tick结束时**的观测值，不能解释为整个训练过程有充足安全余量，更不覆盖tick内部扣费瞬间。

L10敌军配置两系共40人且有Boss倍率，L11普通敌军只有7人、L12为9人；配置标记第二章“骑兵加入”，真正出现骑兵编队要到L17。在这四条固定流里，L11与L12都能由残军一回合通过。当前章节开头形成战后缓冲，玩家无需先补满才可出战，但这两关的轻松通关不证明后续军备健康。
