# P73 粮工增产与冶钢岗位再平衡（2026-09-24）

**文档目标：**按《放置时代》的发展与成长骨架，让不依赖关卡胜利的人口扩容真正转成可持续生产；像素美术和“前段聚落／机巧，后段神祇／西幻”命名方向不变。**代码现状：**P72真实v29档已有城市Lv28、126/126人口，但为了养住203名现存士兵，农田Lv1时要43名粮工，钢只能稳定净产46/s。**本次决定：**只使用现有市场、建筑升级、岗位和在线计时动作验证农田升级的收益；不修改玩家配置、存档、战斗或 UI，也不把当前农田数值误称母本同值。

## 同档实际付款与持续生产

输入`reports/data/p72-pop126-paid.json`独立重载`ok`，第7,554,618在线秒。探针`tools/verify/probe-farm-steel-p73.js`先调用真实市场`exchangeResource('wood','stone',100000)`，木实扣100000、石得60000，使用一次现有高级交易额度。然后逐级调用真实`buildAct('farm')`，每次按`upCost`检查仓容、库存、扣费与完工；建筑施工时增益暂失，探针要求额外保留6000粮，实测全程最低粮**3205.03**，没有借助断粮且不出生的漏洞。

## 母本对应与命名边界

母本`210(1)_unpacked/_analysis/deob_main.js`约偏移1086894的`workShop` 0x3f7a1 名为「牧场」，`LvMax=50`、`Get=[1,0.1,...]`，是工人粮产增益；偏移1086189的`farm` 0x3a981 才名为「农田」，`Get`是食物库存产出。当前我方`CFG.buildings.farm`虽显示「农田」，实际是`buffRes:'food'`的工人增产建筑，`buffBase=0.20`、`buffPerLv=0.25`，Lv5合计+145%，功能更近母本「牧场」，增幅也高于母本每级10%的配置值。当前`upBase`按`1.5^lv`付费，并非由母本上述`Need`直接得出。**本批实付证明的是现行代码可达性，不证明粮食成长曲线已经与母本对齐。**

前中段玩家界面继续保留现有「农田」以避免在未复核像素建筑外观时只改名不改物；后续美术／机制映射应裁定把工坊型增产明确命名为「牧场」或维持现名并调整说明，别将母本两种建筑当成同一条升级。守御之神、神战勋章等后段西幻词不用于本段粮食产业。若要把`+25%/级`改成母本节奏，必须同时重跑从零人口、地契、军粮、兵员与冶钢的真实供需，不能孤立削产率。
