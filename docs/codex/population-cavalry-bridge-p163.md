# P163：28人口的军械接力与骑兵岗位投入（2026-09-26）

## 要回答的问题

玩家感受到“必须打关卡才能增加村民”时，要先拆开人口和战力两条曲线。已有P157／P158零胜场路线能经市场扩容到20人；P161的28人口终档则来自P159战役路线，28人能否完全由零战斗经济达到尚未验证。P162从28人口档续跑时，库存目标虽然有15步兵／13弓手／15青铜刀盾兵，实际编入阵位的却是15名刀盾兵和13名弓手，15名步兵留在预备池。

P163据此检查现有的T1骑兵路径：能否用现有住房与岗位存档真实建训练场、解锁和训练更多骑兵，再观察编队与L17结果。它是成长链验证，不是新增玩法，也没有改玩家运行逻辑。

## 来源与方法

从P161的4粮工／5石工路线精确序列化终档起跑：28/28人口，L1–L11连续胜、0地契，初始资源木370／石1600／粮1037.3256／科技3000／战功56，岗位为木10／石5／粮4／煤6／铜3。P162当前路线起始实际编队为15刀盾兵与13弓手，15步兵在预备池。探针验证P161、P162的来源文件SHA，并把P102脚本只在内存中派生成从L12续跑、骑兵优先占前排、关闭开发侧模拟地契奖励和记录逐兵种入场数；未编辑P102或游戏源码。

骑兵训练使用当前真实动作：建造骑兵训练场，调用`unlockUnitRoot('cavalry_t1')`，通过`train()`排队，随后用真实`tick()`等待队列扣费与生产；战役使用真实编队、战斗、伤亡、补兵、存档和`settleOffline()`。普通岗位对照保留原4粮工分配；另有一个19骑兵敏感度分支，通过真实`setPopAlloc()`把28名工人调为木11／石5／粮12／煤0／铜0，以检验岗位倾斜能否支付军备。

随机种子3用于1／5／7／10／15／19名骑兵剂量扫查。对最高完整训练数量10与相邻数量7，再用种子11和29复验。若19名粮食倾斜路线能过L17，则同样用11和29复验。所有会话请求每600模拟在线秒后结算28800秒离线；P163记录食物不足导致的实际截断时长，不把短结算写成完整8小时。

## 结果

当前工作树启用`unitCapBoost`，一级骑兵训练场的T1上限为19（配置式为基础15＋每级4，训练场Lv.1）。这不是原始未增强上限，也不代表19名能由任何岗位档实际训练。训练场建造实付木220／石160／粮180；侍从骑士解锁实付木300／石200／粮250、科技250和战功8；每名训练成本木120／石80／粮150。

基础岗位扫查中，5、7、10名骑兵均在种子3打过L16，但面对63人、加权攻击567的L17仍败；10名与相邻7名在种子11／29的6次首战也全部败于L17。骑兵越多并没有在这些对照里稳定跨过阻挡关。1名骑兵的队伍入场比基线少4人（24人），所以不能只看仓库里的骑兵数量。

19骑兵的岗位倾斜路线证明同一批28名村民可以通过实际转岗把军备训练到当前一级训练场上限。训练19人仅花111模拟在线秒，没有离线等待，训练完成后粮食剩30.57；随后L12–L17每场胜后利用600在线秒与真实离线结算补兵。该固定种子通过L17，却在72名、加权攻击648的L18三回合败下；重建库存再试仍败。另两个固定种子都在L17败。因此不能把“19骑兵种子3通过L17”当作通关保证。

## 设计建议

保留“人口靠住房、口粮与时间自然增长，关卡用于加速军械和资源路径”的分轨结构。零胜场可达20人的现有证据意味着，不能把战斗胜场设为早期人口唯一入口；但也要实测零战斗路线从20继续到24、28，而不是把P161战役终档误当成经济保底。

把岗位调度当成军备成长的可视化决策：常规产业岗位支撑持续经济；到军械检查点时，玩家可以临时把工人转向粮、木、石，训练一波机动部队，再根据兵损回到产业岗位。P163只证明“木11／石5／粮12”在同一28人终档可训练19骑兵，并得到种子相关的战斗结果；煤铜停产、补给持续性和其它岗位方案还要验证。不能将此比例写成固定玩家答案，也不要提高出生倍率来替代军粮与阵位校准。

主题上，本批只按内部兵种键`cavalry_t1`做开发验证；当前玩家名称“侍从骑士”偏西幻，后续对齐机械军务主题时可考虑改作“侦察骑兵”或同类中性军务词。本批未改名称、UI或美术。
