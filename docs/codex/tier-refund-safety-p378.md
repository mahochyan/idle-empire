# 营地升阶与兵种研究的退款安全（P378）

2026-09-29；`master`，基线 `f85e1c8624de8c9e17f7724373e65899d1085cdf`。修复前，`refundUnitsByLine` 虽只给指定阶级及以下兵种计算退款，却清空同线所有阶级的兵池、远征和驻军。因此研究另一条T2分支时，旧档已有的T3兵会无退款消失。当前步、弓、法营地均配置T3→T4升级费用，却没有任何相应T4兵种；完工仍退役整支T3军队并取消队列，造成高成本升级后暂失战力。

现统一以训练线和 `tier <= maxTier` 筛选可退役兵种，使退款、兵池、远征、驻军和训练队列作用范围一致。营地完工时仅在配置存在下一阶接班兵种时退役旧兵；T0→T1等既有接班兵种的规则保留，当前三座营地T3→T4则保留T3兵力和队列。升级本身、费用、时间和保存路径未改；没有新增存档字段。

[真实函数回归](../../tests/progression/tier_refund_safety_p378.js)在修复前0/4通过、退出1；修复后6/6通过、退出0，覆盖兵池、远征、驻军、队列、跨分支研究、T0→T1旧规则、三营实付T4以及保存重载。`node tests/progression/combat_guards.js` 13/13、`node tests/progression/military_metals.js` 23/23通过；`node --check math.js` 与 `git diff --check` 退出0。Node测试使用DOM/存储替身；最终真实Edge回归由合并UI后的整体验证记录。已知边界：T4仍无可训练的新兵种，故这笔营地升级尚不是完整兵种成长收益。

回退可撤销 `math.js` 中本项两处改动并移除新增测试；但这样会恢复已确认的高阶兵无退款丢失缺陷，不建议对现有存档使用。
