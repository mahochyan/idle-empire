# P181：双后排游侠承接第18—20关（2026-09-26）

> 历史基线：本报告的第20关为P186调整前的9 HP配置；文中“现行”指当时锁定的输入快照。正式关底配置见[P186](live-l20-boss-p186.md)。

## 同源起点与验证口径

[探针](../../tools/verify/probe-current-l18-l20-archers-p181.js)从[P178原兵线](current-l18-l20-bridge-p178.md)的四支第17关真实获胜来源重建序列化`rts_save`：固定随机流种子1／42，各含现行第3关首次胜利`+6拓居令`及隔离VM中关闭该奖的对照。P181逐项核对本次重建的L17战后状态与P178历史状态相同；P178的17项历史输入除`levels.js`整文件文案哈希外均校验，L18—L20敌阵的兵种、数量、倍率也与P178逐项相同。L17当前配置有63名敌兵，重建的L17结果与旧记录逐字段相符，不凭可见名称推断数值。

从**每份相同的L17胜后档**分叉出两档目标：青铜刀盾兵15＋民兵15＋游侠30，或青铜15＋民兵15＋游侠36。30游侠用已开放的后排两格各编15；36游侠另在中排编6。现行营帐2级允许15人／团，弓兵营地T1 1级允许拥有36游侠。每场先调用真实`train()`排队、逐秒`tick()`生产，按真实编队动作入场，随后运行当前异步战斗回调、结算、保存和重载；若获胜，则补回相同目标再战下一关，最多等待7200模拟在线秒。没有注入资源、人口、兵力、科研或胜场，也没有建新建筑、使用市场／离线／驻军。秒数仅是`tick()`数量，不含战斗动画和真人操作时间。

## 实战结果

表中每个关卡单元为“战前补兵在线秒／战斗回合／战损总人数”；粮低位是L17胜后至本分支终点每个在线tick结束时观测到的最低余额。四支有奖分支均依次胜第18、19、20关，且每场实入场人数与各自目标一致。

两支**无奖来源档**在第17关后均只有19人口、4粮工，当前奖对应20人口、5粮工。无奖的30／36游侠四个分支虽然`train()`全部接受请求，但第18关补兵等满7200秒时粮余额均为0、青铜刀盾兵队列仍报“资源不足，暂停生产”，故四支都未实际开打第18关：种子1的30／36档分别只拥有13／10青铜（目标15），种子42分别拥有13／6青铜。36游侠无奖种子1还缺2民兵与2游侠。此处的阻挡是**同一旧岗位配置的经济与训练门**，不能计成战斗失利，也不能把有奖分支的四胜外推为无奖策略不可通关；岗位调整尚未试验。

30游侠方案相对[P178](current-l18-l20-bridge-p178.md)的13游侠、43人原阵，从同一L17胜档增加一个后排兵团：P178种子1两支第18关胜、随后败第19关，种子42两支败第18关；本批有奖的种子1／42在60人实编下都过第20关，但无奖的60人队伍在原岗位下补不齐。36游侠方案虽也过关，却比30游侠多等5300／4707在线秒，且粮低位仅0.26／0.15。这些成对结果表明“多练6名游侠”在本两种随机流和岗位方案里未带来更快、更稳的承接，不能把36人目标设成推荐保底。

按实际产出数量核算，种子1／42有奖30游侠在第18关前分别生产5／14青铜、6／15民兵、17／20游侠，总训练材料分别为木2520／3600、石920／1400、粮2710／6100、铜500／1400；36游侠相应为木3240／4320、石1160／1640、粮3010／6400、铜500／1400。粮食总产出成本可超过3000的当前仓容，因为每个士兵在队列完成时分别付款、期间持续产粮。探针在隔离VM包装真实`payTrainingCost()`，逐次核对`S.res`扣额，再汇总与队列实产数×当前兵种成本相等；排队瞬间不扣材料，停产tick不计作已支付。在线净余额还受生产、居民口粮与军粮维护影响，不能把训练费用总数当作单次采购门槛。

第20关在四支已触达路线均1—2回合胜、战损7—18人；前一关第19关需3—4回合且战损20—30人。[现行敌阵](../../levels.js)第19关为9团78生命，第20关同为9团却仅9生命，首领攻击×1.35、防御×1.3。这是本批**实际到达关底后的压力回落**，与[P180骑兵线](current-l18-l20-cavalry-p180.md)1—2回合过首领互相印证；仍须以同档替代敌阵比较、补兵成本与首通奖励一起定稿，不能只凭静态HP改Boss。
