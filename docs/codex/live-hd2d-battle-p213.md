# P213｜第 29 关真实浏览器 HD2D 战斗随机流审查

结论：在本批两份第 29 关 73 人实付战前档和固定流 1、15 中，真实 Edge 页面启用 HD2D 与强制走视觉回退时，异步战斗的随机调用轨迹、胜败、回合、战损、奖励及去除保存时间戳后的完整战后存档逐项相同。没有观察到 HD2D 消耗战斗随机数或改写战斗结算。流 15 在 Edge 两种视觉模式下均全军覆没；此前 P211 的流 15 逆序阵获胜和 13/16 通关数只能作为 **Node VM 指定固定流结果**，不能直接当成浏览器通关数。

## 与 P211 Node VM 的差异定位

为追查流 15 分叉，另把**同一份浏览器形成的战前完整档**交给 P211 所用的 Node VM 加载并执行相同正式 `math.js`。这是辅助定位，不代替上面的真实页面验收。Node `v24.19.0` / V8 `13.6.233.17-node.51`；Edge UA 为 `Edg/153.0.0.0`。两环境战前双方兵团的类型、位置、人数、HP、攻防、速度、tag 及战术逐项一致；种子相同，开战时均消耗 0 次，首 11 次随机值逐个相同。

流 15 的第一次 `battleTurn()` 中，同速兵团排序都调用正式 `math.js:3338` 的随机比较器：Edge 先消耗 **11** 次，随后第 12 次进入 `battleTurn`；Node VM 先消耗 **13** 次，随后第 14 次才进入 `battleTurn`。两边随机调用轨迹均只指向 `math.js`，没有 HD2D 或背景 tick 调用；Edge 的前两个视觉模式轨迹完全相同。排序随机消耗不同后，首个猎风目标在 Edge 为农民，在 Node VM 为魔法学徒；最终 Edge 败、损 73、共 229 抽，Node VM 胜、损 49、共 192 抽。流 1 则两环境同为排序先 10 抽、胜、损 37、共 168 抽。

因此已定位到同速排序处的调用次数分叉。当前 `sortFn` 对同速项用 `Math.random()<0.5` 返回正负号，比较结果不具备稳定顺序；Edge 与 Node VM 的排序调用路径不同，是这一固定流不可跨环境照搬的直接机制。未独立剖析 V8 内部排序实现，不能进一步声称特定引擎版本缺陷。尤其 [P211 的 10/16 与 13/16](live-l29-order-sweep-p211.md) 均应限定为其 Node VM 环境的 16 条固定流观察，不能据此推断真实浏览器的 16 条流通关数，更不是玩家胜率。
