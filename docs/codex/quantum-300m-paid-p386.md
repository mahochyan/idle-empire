# P386｜星阵第二研究的 3 亿知识仓入口实付续线

日期：2026-09-30。本批从 P385 十轮晶域终档继续，验证现有蒸汽科研链能否真实支付到**单笔 3 亿知识的仓容入口**。这对应母本星阵第二研究的费用门，不等于现游戏已实现星阵研究，也不等于量子时代的单笔 **30 亿**知识门。本批只生成隔离探针、实付开发档和账本；没有修改玩家运行代码、UI、美术、策划文档或真实玩家存档。

## 同一随机流的付款与产出

[P386 探针](../../tools/verify/probe-quantum-300m-p386.js)先在无写入 VM 中重放 P385，所得终档原文 SHA-256 与输入 [P385 终档](reports/data/p385-after-ten-crystal-cycles-save.json) 的 `9f181d49eea30aaad3d6ce0bd4d2e9f66cc9d38b17dac902a02de1fb6fb36e83` 完全一致，才在**同一个 VM** 继续战斗。P385 的本地存档不序列化随机数状态；此法恢复末态 `3635533231`，P386 全程没有重新选种、重置随机流、补库存或免费恢复士兵。每一场都用已有的血剂 3 → 净化剂 1 常驻兑换把晶域警戒 5000 降为 4900，调用真实材料战；战胜后按既有岗位、逐秒 `tick()`、真实 `train()` 扣费和编队动作补回 626 出战人。每次升级均调用 `upgradeEraStorage('steamKnowledge')`，核对实际扣费、仓容变化及保存重载。

## 完成的门与未完成的门

**3 亿仓容入口已在这条实付续线上验证。**当前玩家代码没有星阵研究或星阵容量乘区；母本还要求相应兵种觉醒 20 阶、至少 50 星，P386 源档仅 6 阶、7 星。因此不能把 3 亿库存写成已支付星阵第二研究，更不能据此把星阵乘区提前计入量子仓。现有 `researchScience('sci_quantum_age')` 在 300,022,549 知识／4,042,870 勋章时返回 `insufficient-tech`，研究前后知识和勋章均未扣、量子科技未解锁；量子仍需单笔 3,000,000,000 知识。第 100 关“全科技后才可打完”的终局条件也未由本批证明。

探针在 Node VM 中模拟 DOM、localStorage、战斗计时器，调用的是实际业务动作；一条固定但**连续**的 19 胜流只能证明存在这条可付路径，不能估算一般胜率、新档自然到达时间、离线短会话表现或所有阵容的失败恢复成本。P385 原脚本的开发档写入由只读包装截住，重放仅用于恢复未持久化的随机数状态；P386 最终只写自己命名的两份数据文件。
