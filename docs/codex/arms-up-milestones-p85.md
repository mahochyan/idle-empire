# P85 兵装十星与百星阶段奖励（2026-09-24）

## 母本目标与我方现状

策划路线要求保留母本逐兵长期成长，再按我方单位生命口径和现有战斗逻辑适配。P83已按母本340xxx攻击／生命／防御兵装接入逐星线性加值；P84实付铁枪兵一星为攻击+1，但12组守御4500对照结果无变化。本轮回查本地`210(1)_unpacked/_analysis/deob_main.js`实际属性重算函数，发现母本兵装还有独立的阶段加值：

- `adjustArmyATK`（源文件偏移约1,288,640）：每星仍加攻击兵装的`AddATK`；另加`floor(初始攻击 × floor(攻击星数/10) × 20%)`。
- `adjustArmyHP`（偏移约1,290,877）：每星仍加生命兵装的`AddHP`；另加`floor(初始生命 × floor(生命星数/100) × 20%)`。

这些是每跨一档累加一次，不是达档后只领一次。它们与将魂石`armyLvUP`升阶是两套独立系统；本批不接将魂石、觉醒或核源星阵。

## 本批改动与映射

在`CFG.armsUpMilestones`集中定义攻击每10星+基础攻击20%、生命每100星+基础生命20%。`armsUpBonus`将逐星线性奖励与相应累计档位奖励相加；攻击奖励进入既有`weaponAttack`，生命奖励以我方`hpPerSoldier`为基数还原至母本整数生命（乘100）取整，再换回我方战斗HP（除100），进入现有`battleVitals`。防御仍按母本当前已核实的每星加1，没有自行添加未找到的阶梯。

当前我方配置中的基础攻击作为母本“初始攻击”的映射，装备攻击继续按既有装备加值单独相加；基础单兵生命已按母本HP/100映射。该选择避免把装备奖励也再次乘入兵装里程碑，但与母本含资源／将魂等在内的`getArmyInitATK`并非全等，后续其它成长层接入时须共用账本复核。科技页显示“攻击每10星追加基础属性20%；生命每100星追加基础属性20%”，各兵种三维“当前+值”改为调用同一属性函数，避免UI只显示线性项。

存档仍v31，复用`armsUp`中的星数，不加字段、不迁移；已存到10星攻击或100星生命的旧档在读取现代码后会立刻得到阶段奖励。属性加值只进入我方远征与驻军共用的已有读取路径，不改敌兵和持久人数。文件`config.js`、`math.js`、`ui.js`已修改；没有修改`index.html`缓存版本，因为本批尚未发布。
