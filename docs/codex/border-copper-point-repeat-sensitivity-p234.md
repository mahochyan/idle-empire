# P234：铜脉点位“每胜加1级”敏感性上界

日期：2026-09-26。结论：**每胜加1级使点位更接近可定价的长期产能，但仍不能据此确定首个边疆区域的正式收益。**30胜时，若只激活铜点，其基础产速到60铜/分钟，相当于当前1名铜工；取得这一级数需要重复承受战损、木粮补兵和仓满浪费。本批只新增 [纯账本脚本](../../tools/verify/model-repeat-copper-point-p234.js) 与 [模型JSON](reports/data/p234-repeat-copper-point-model.json)，未改正式代码、UI、总策划或真实存档。

**后续源码复核（P235）：**母本`winMiddleWar`的25段采集点分支每次胜利确实直接加`floor(Get数量×警戒奖励倍率)`级，封顶500；早期低警戒、静态数量1时即每胜+1级，且该分支无额外随机抽取。[证据与调用链](border-point-source-correction-p235.md)。下文“每胜+1”仍只是**我方简化模型**：冻结警戒倍率、敌阵、战损与补兵秒数，并未模拟母本后段单胜可能超过1级或我方正式奖励。

## 来源事实和反事实规则

母本 `560005` 铜矿山贼的静态`Get`含`[250005,1]`采集点与`[160004,400]`铜钱；`250005`铜点基础`collect:Get=[150006,2]`。`winMiddleWar` 在胜利时遍历本次 `Get`，25段点位分支每胜增加`floor(Get数量×警戒奖励倍率)`级，封顶500，未见首胜门或这条分支的额外随机抽取；低警戒倍率1时才严格是每胜+1级。`autoCollect`一次选定一个点，每60000毫秒以点位等级×基础2铜为基数，再经过加成入库。母本铜钱400不是我方`coin`的已定价格；本批不计这项收益。源及路径详见 [P229](development-frontier-candidate-p229.md)、[P232](border-copper-point-budget-p232.md)、[P235](border-point-source-correction-p235.md)。

本模型从P229 R1同一份实付18人口档的16条固定流出发：敌方步兵`[5,4]`＋弓手`[2]`，16流首战全胜、损1–7兵，合法调1名石工至木岗后，实际补兵81–380在线秒，付款后粮底最低0.034。当前铜工3，每秒合计产3铜，铜库存57/上限800。每个模型分支把**同一条首战损失、实付补费和补兵秒数**重复5、10或30次；胜利后点位等级依次1、2、…、N，60秒时钟跨胜场延续，始终只激活铜点。只计算补兵窗口内的点位脉冲，不加战斗动画时间；所有脉冲都假设不被仓容截断，也不计母本科技加成或我方其它铜用途。这是对应时间窗口的**理想全收上界账**，并非真实连续战斗/经济函数验证；敌阵与战损均不随警戒值增长。

## 仓容截断反例与现有岗位

P229首次补兵里，原3铜工单独产铜 `3×补兵秒` 已逐流超过对应铜付款100–500，扣款后还净增143–640铜。把同一流机械重复，初始57铜、无仓容限制时，第5／10／30个补兵窗口后“工人＋点位−训练铜费”的库存理论值为808–3443／1633–7153／5599–25167，均可能大幅超过上限800。超过上限的**工人和点位合计产出**在当前模型至少要丢弃8–2643／833–6353／4799–24367铜；这不能直接归因于点位，但足以说明上表全收是不可当作实入的上界。

更直观的无支出反例：假设仓库从P167的57铜起、仍有3铜工每秒产3铜，而点位已分别达1／5／10／30级。一小时的点位名义铜量分别120／600／1200／3600；在800仓容下按每秒工人生产和每60秒一次点位脉冲，实际点位只入8／30／60／180铜，约第245／238／228／188秒仓满。若30胜后仓库恰为800，随后不训练、不研究、不扩仓，任何等级的铜点这段时间实入都为0。真实连续战中训练付款会暂时腾空铜仓，但P229仅保存每场补兵汇总，缺逐秒付款与点位脉冲的交错轨迹，故**无法从本批算出真实点位实收或净收益**。

## 对下一批定价的判断与护栏

“每胜等级+1”符合母本**低警戒期**的25段点位结算，也能让模型中30胜后产速达到1铜工的量级，值得在隔离后端原型中验算。它仍**不足以作为正式价格**：母本虽有500级上限，后续警戒倍率会改变单胜加级；我方上限与敌阵尚未定；同一首战敌阵和战损不可能替代30场真实连续变化；玩家何时研究/消耗铜、一次只能激活一个采集点、铜仓容升级、粮低于1时的稳定性、离线规则和铜钱400对应的我方回报都没有同档结算。

实施护栏应是：独立点位等级和激活ID有可验证上限、持久60秒计时及旧档默认0；每胜是否加级由正式规则明确并防重复回调，未激活点不产；每个脉冲按仓容记录名义/实入，不挤占现有岗位产率；在线/离线采集政策分别明确并测试，保存失败回滚；复刷奖励与铜钱、粮、木石费用单独做实际净账，人口出生与市场购契保底不依赖胜场。下一次可从P167完整档出发，在**新后端真正实现后**连续打5、10、30场，逐秒记录点位脉冲、训练扣铜、仓满、粮底、保存重载与警戒变化，再决策我方敌阵和奖励；本批模型不注入任何铜进真实档。
