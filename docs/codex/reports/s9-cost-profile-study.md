# S9 沙箱研究 · 成本剖面（我方指数 vs 竞品分段线性）

> **本报告未改任何游戏文件**：成本剖面通过 `curve-sim --cost=` 在 vm 沙箱内覆盖 `upCost` 实现（测试侧工具），50h 实测。

## 1. 竞品成本公式（原文实证，@1485372 `addWorkShopLv`）
```
per = Need[res] / 3                      // 每级基准增量（某建筑特例 = /5）
lv < 10   : cost = base + lv × per
10 ≤ lv < 20 : cost = base + 9×per + (lv−9)×per×5
20 ≤ lv < 30 : cost = base + 9×per + (lv−9)×per×10
30 ≤ lv < 40 : cost = base + 9×per + (lv−9)×per×20
40 ≤ lv < 100: cost = base + 9×per + (lv−9)×per×40
```
即：**前 9 级线性（斜率 ×1）→ 之后按段整体跳到 ×5 / ×10 / ×20 / ×40**（分段**阶梯斜率**，非边际累加）

**我方现状**：`upBase × upCostLv^lv`（**指数**，如仓库 1.3^lv、营帐 1.7^lv）——**形态根本不同**

## 3. 判读（证据支持）
1. **`seg` 让采集 buff 建筑真的升起来**（lv9/7/9 vs 3/3/2）→ 直接解决切片 8 报告里的 **G5/O12**（乘区只有 ×1.75 的问题）；乘区起来后 木/食 产量高 2-2.5 倍
2. **`seg` 避免了后期食物枯竭**（50h 食 430425 vs 169）——枯竭根因是"铸币耗粮随等级涨、但农田 buff 涨不起来"，`seg` 让农田能升到 lv9
3. **`seg` 的升级分布更"铺开"**（营帐触顶 10、仓库 11、市场 11），`exp` 则是"少数建筑跑高（步兵营26/学院27）+ 多数趴 1-3" → 后者是"单点跑飞"，前者更接近竞品"多建筑并行升级 + 工坊 50 级"的观感
4. **但 `seg` 本身并未造出"3-15h 中期墙"**：50h 内最高仅 lv19（步兵营/学院），而竞品的斜率跳变墙在 lv20/30/40 段 → 中墙要等更久；**中期墙应由"科技阶梯成本"承担**（竞品的中墙正是研究树知识门槛 ×1.4→×3333）
