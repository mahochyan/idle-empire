## 四、实现要求

### A. 集中序列化、校验和迁移

保留 `rts_save` 为主键，保持所有现有持久字段的兼容读取。先列出字段映射，特别核对 `garrisonForm` 与 `S._garrisonForm`。

在没有既有版本机制的前提下，新增递增版本字段 `v` 和保存时间 `ts`。`ts` 表示本次快照保存时间，单位为毫秒；本轮不得依据它发离线奖励，也不要把它宣称为已经设计完毕的离线结算游标。无 v 的旧档作为 legacy 输入迁移。

可采用 `serializeSave`、`validateSave`、`migrateSave`、`loadSave`、`writeSave` 等职责分离方式，函数名以项目风格为准，不要求为这些职责单独建框架。

处理顺序必须能够检验：读取原始文本 → 在候选对象上解析/校验/迁移 → 备份 → 提交成功 → 才使用新状态。迁移必须可重复执行而不重复增加资源、兵力或进度。

校验至少覆盖：顶层结构、版本、关键映射与数组、数值类型/有限性、合法零值、必要的单位/建筑/关卡引用。不要使用任意输入对象直接展开或深合并进 S。缺失的可选字段使用独立的新建默认对象，不能引用已经被当前游戏改过的 S 作为默认模板。

不能因为旧档超出当前资源/兵力上限就直接裁剪；无法安全解释的数据进入保护/恢复流程，并明确指出问题。已支持版本的既有字段应完整往返；未来版本不支持时拒绝写回，不能把它降级保存。

### B. 原档保护与备份

建立数量受控的最近有效备份，以及独立的迁移前原始副本。具体附属 key 集中定义并写入文档，不能把迁移前副本当普通轮转备份每分钟覆盖。

迁移、导入和恢复必须在覆盖主档前成功保存可恢复的原始数据。若备份写入失败，终止覆盖。正常自动保存不得用损坏或空白默认状态覆盖最近有效备份。

所有读取/写入路径处理存储异常。写入失败时保留现有主档，明确提示“未保存”，不要每个 tick 连续弹窗。不要为了释放空间删除主档或唯一备份。

损坏主档/不支持未来版本的启动场景：显示保护提示，保留原始文本，并阻止包括定时保存、按钮保存和退出保存在内的全部自动覆盖路径。允许导出原始文本、检查/恢复有效备份。不要静默开新档或自动回退到更早进度。找不到有效备份时也不能偷偷替换主档。

如任何步骤因容量或权限失败，保护副本和主档的边界要在测试中验证，不能只测试正常路径。

### C. 最小存档管理界面

在现有设置入口添加存档管理，复用现有 UI，不新增导航页或换皮。

导出：正常模式导出当前有效状态的 JSON；保护模式提供原始异常文本导出。支持文本框手动复制，不依赖剪贴板授权成功才能取回存档。

导入：粘贴 JSON → 校验 → 展示版本/城镇/进度等可用摘要 → 用户确认替换 → 备份 → 写入成功 → 完整重载并通过标准加载流程进入游戏。解析、校验、备份或写入失败时，不更换 S，不刷新，不修改原主档。

恢复：显示最近有效备份摘要，确认后按与导入相同的安全流程处理；无效备份不能恢复。

避免旧战斗回调污染新状态：本轮采用简单规则，远征、训练场或驻军战斗仍有可能回写状态时，禁止导入/恢复并给出明确原因。核查真实状态机与回调，不只判断一个 UI 是否关闭。普通的建筑和训练队列无需被清空。

导入内容作为文本处理，不能插入可执行 HTML。不要回显完整存档到控制台、外部接口或诊断事件。

### D. 最小诊断与测试入口

需要能区分读失败、解析失败、校验失败、备份失败和写失败。可采用结构化返回值加有限的本地诊断摘要，不需要完整 analytics 系统、设备 ID、网络上报或 A/B 分桶。诊断本身失败不能反过来使游戏崩溃。

测试调用真实序列化、迁移和存储封装。优先复用已有环境；没有环境时建立最小开发侧测试脚本，提供准确命令及环境版本。通过测试替身控制存储错误和时间，但不能复制生产实现作为测试对象。

## 五、验收矩阵

“通过”必须有已运行证据。相关浏览器用例未运行时标记“待验证”，不能把整张任务写成已验收。

| 编号 | 场景 | 必须观察到的结果 |
|---|---|---|
| S01 | 没有存档的新开局 | 正常初始化，保存后再加载一致；缺档与坏档分开处理 |
| S02 | 无 v/ts 的 legacy 旧档 | 所有现有持久字段保留，迁移前原文可恢复，不赠送/扣除资源 |
| S03 | legacy 缺少可选字段 | 独立默认值补齐；不会带入另一个游戏状态的数据 |
| S04 | 合法 0 值及普通非零进度往返 | 资源、队列、阵容、城镇、驻军、科技、精魄不丢失；合法 0 不变成缺省值 |
| S05 | 重复加载/迁移/保存 | 除预期元数据更新，游戏进度不被重复改变 |
| S06 | 主档是截断 JSON、null 或不合法结构 | 原文保留，明确报错；推进自动保存周期并调用其他 save 入口仍不能覆盖它 |
| S07 | 不支持的未来 v | 不强行降级、不写成当前格式；允许导出原文 |
| S08 | 读取权限错误、备份失败、主档写入失败 | 分类提示；不虚报成功，不先换 S，不损坏可恢复原档 |
| S09 | 导出 → 导入 → 重载 | 核心进度一致；替换前存在原档备份 |
| S10 | 无效导入、用户取消、无效恢复备份 | 主档与当前状态不被替换，无额外扣费或清空 |
| S11 | 战斗进行/异步回写未结束 | 导入与恢复被安全拒绝；战后正常路径可使用；没有旧回调串写 |
| S12 | 历史超限数据或未知引用 | 不静默裁剪/删除进度；清楚报告不能安全迁移的数据并保留原文 |
| S13 | 真实浏览器新档与旧档冒烟 | 启动、采集、建造、训练、编队、第一关战斗、设置和刷新，无本轮引入的错误 |
| S14 | 手机窄屏与输入交互 | 设置入口可操作；粘贴时输入不被 tick 刷掉；确认/错误提示可见；文本不会作为 HTML 执行 |

旧档样本用可审查的合成 fixture，不提交玩家私人存档。至少有一个覆盖当前 save 所有持久字段的非默认 fixture，不能只测空对象或刚开局的状态。

配置/关卡已有错误、跨标签页并发写入与其他超出本轮的边界，必须诚实记录。本轮不承诺解决所有并发与历史兼容问题，不能用“已备份”掩盖未验证的写入窗口。
