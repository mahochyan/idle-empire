# P401｜实付兵装对第100关的实际作用

从 P400 同一量子实付档取两份连续保存点：[兵装研究已付、尚未强化](reports/data/p400-armament-natural-route-save.json)与[星际先遣兵攻击／生命各实付一级并通过材料战](reports/data/p400-armament-natural-invested-save.json)。两档皆为 v34，正式第100关已通关，均可合法重战，出征阵容同为626人。前后仅比较同一条自然付款路线的兵装投资；科技已支付、资源差异、材料战奖励均按真实动作保留，不向战斗存档注入军力。固定 RNG 种子1–16，每场从各自原档独立加载，调用真实 `selEnemy(99)`、`openBattle()`、异步回调、结算和重载。

正式敌阵两边全部获胜，因此**当前第100关没有验证出这两级兵装是胜利所必需**。正式配置下两级平均少损约16.69人，但逐种子差值为少损103到多损74人。隔离增压只改 VM 内的敌组人数，升级组在2640敌反而少胜两流；2860敌又多胜一流。战斗的目标、击杀时点和随机消费会随属性改变，故不能假设固定种子的战损/胜负单调改善，更不能拿一个候选敌数直接落表。16条工程固定流不是玩家胜率。

设计结论：目前若仅把 `sci_astral_armament` 增设为第100关资格门，会增加一笔很长的付款等待，却没有证据证明玩家须借此获得有效终局战力；这仍偏离“全部必要科技之后才能攻克的陡峭主线”。在定稿关卡门之前，应先用真实可支付的多级兵装、量子兵入阵与终局成长路线，比较第91–100关连续战损和失败后补军，再选能让科技和战斗能力共同起作用的压力点。既有通关存档必须保留胜场和重战入口。

复跑：Windows PowerShell / Node v24.19.0，`node --check tools/verify/probe-stage100-armament-effect-p401.js`、`node tools/verify/probe-stage100-armament-effect-p401.js --pilot` 与完整16流命令 `node tools/verify/probe-stage100-armament-effect-p401.js` 均退出0。完整[逐场账本](reports/data/p401-stage100-armament-effect.json)含原档及运行文件 SHA-256、每场敌方总人数/HP、出战星际兵攻血、战果、战损、回合、回调数、终档哈希；执行前后运行文件散列相同。P401 只增加开发侧探针和报告，没有改变正式敌表、门、存档或 UI。撤回本项仅移除这些证据文件；浏览器与 Android 战斗未在此探针中运行。
