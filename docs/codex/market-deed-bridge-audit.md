# 人口扩容的早期地契续供：市场桥接审计（2026-09-23）

## 结论与证据边界

当前并行实施中的新人口模型给新档 **0／4 实际人口、30 地契**，村庄从 Lv.0 开始，每级加 1 容量，前四次花 `5+6+7+8=26` 地契，使容量从 4 到 8、余 4 地契；第五次需 9。若仍只能在 `sci_coin` 研究后建市场，玩家会在 8 容量处等待末端货币研究才能继续用经济换地契。只前移**市场**到 `sci_copper`，保持**铸币厂**在 `sci_coin`，即可用已有的木／石／粮卖出换金币，再以金币买地契；`sci_copper` 在长、短两套科技表中均存在，避免关闭长阶梯开关时市场科技 ID 不存在。市场现有建造费用和汇率不需要为了首轮续供降低。

这是一项**我方适配方案**，不是宣称《放置时代》开局就开放市场。母本源码审计确认其新档地契 30、村庄／小镇／城市扩容费用基础值 5／15／30，并找到银两购买地契的市场商品；母本的银两、市场、铸币前置在 30 地契耗尽前是否全链可达，尚无实机或完整回放证明（`docs/codex/era-mapping-audit.md`“补证：离线人口与新档地契”）。本方案遵循 `策划文档.md` §8.4 与 `docs/codex/人口与城镇扩容方案.md` 的明确目标：地契续供不必打关卡，也不能被隐藏的日界强制阻断。

现有 12 条汇率按不重复节点的简单闭环枚举，最大乘积为 `coin→stone→coin = 6×0.14 = 0.84`；`coin→deed→coin = 0.01×80 = 0.8`。向下取整不会增加回路收益。这个结果只覆盖当前列出的汇率；增加新价目后必须重验**全部多步环路**，不能只检查每对往返。

## 可执行的最小桥接规则

1. **前移市场建筑门，铸币门保持原位。** 长链 `sci_copper` 需要先取得 `sci_prospect`，合计支付 400 科技点；短链同 ID 也存在，当前费用为 10。市场建造动作、建筑卡、科技解锁说明三处须一致；`sci_coin` 继续解锁铸币厂和成熟市场价目。已建成市场的旧档不能因门调整失效，已研究记录照常保留。
2. **分两段开放现有汇率。** 初级市场仅开放 `wood/stone/food→coin` 与 `coin→deed` 四条；研究 `sci_coin` 后开放其余价目，包括 `deed→coin` 和金币换基础物资。如此开局的 30 地契不能过早被兑换为其他货物，金币生产仍要等铸币厂。初级价目只换出金币或买地契，已列图无正收益环路。
3. **地契供应链不占共享 5 次／日。** 上述四条初级价目按现有汇率、库存和仓容成交，但不增加 `dailyCount('market')`。其余价目继续保留用户已定的 5 次／日及本地 0 点日界。只豁免 `coin→deed` 仍不够：每次扩容还要先卖木／石／粮，卖出也会耗尽共享次数。若以后增加地契直接交易，须明确它是否属于同一发展供应链。无限次不等于无限产出，早期速度仍由工人产率、粮食、仓容及地契线性涨价约束。
4. **用一个动作校验函数统一 UI 与交易。** 先验证市场已建且 `state==='idle'`、相应科技已研究、该费率属于已开放阶段，再验证 `qty` 为有限正整数、来源足额、输出为有限正数、目标容量可完整接收。否则拒绝交易，不扣来源、不计次数；禁止当前“扣足额却只存到剩余仓容”的静默损失，也不要把 0、负数、`NaN` 悄悄改成 1。UI 只展示动作函数允许的选项，并显示兑换后所得和容量缺口；动作函数独立执行相同校验，防脚本直调越权。
5. **保存成功才报告成交。** 当前 `exchangeResource()` 先改 `S.res`／`S.daily` 再调用 `save()`，却忽略保存结果；备份或主档写入失败仍返回成功。应在失败时恢复本次的两种资源和日计数，保留原始 `rts_save`，返回明确失败并允许手动导出。重复提交同一交易请求应只成交一次，但不能按“参数相同”禁止玩家有意重复兑换；可由 UI 请求令牌或一次点击的状态控制达成。不要为这一桥接重新设计整个存档系统。

### 一次真实函数的反事实探针

使用 `tests/progression/harness.js` 的 Node VM 载入采样时真实代码，仅在 VM 内把 `CFG.buildings.market.needScience` 从 `sci_coin` 改为 `sci_copper`；**没有修改磁盘代码、没有取消现有 5 次日限、没有利用市场直调旁路**。新档先真实调用 `upgradeSettlement('village')` 四次、建学院；在线每秒调用 `tick()`，人口到位时通过 `setPopAlloc()` 分工，有科技点即依序调用 `researchScience()`，有材料后调用 `buildAct('market')`。仓库与生产未直接赋值，驻军随机事件在既有 harness 中关闭，localStorage 是内存替身。

| 事件 | 游戏内秒 | 真实函数结果 |
|---|---:|---|
| 四次村庄扩容 | 0 | 地契 30→4，容量 4→8，实际人口仍 0 |
| 探矿术完成 | 101 | 学者岗位累积并支付 100 科技点 |
| 冶铜术完成，市场开建 | 374 | 再支付 300 科技点，市场建造费照旧支付 |
| 市场竣工 | 384 | Lv.1、空闲；铸币厂仍未建 |
| 卖 9000 木、买 9 地契、升村庄 Lv.5 | 649（10 分 49 秒） | 两笔交易各成功，市场当日计数 2／5；支付 9 地契后容量 9、实际人口 8、地契余额 4 |

这个结果只证明**将门前移到 `sci_copper` 在该脚本策略下可达**，不是最短路线、现实操作时间、浏览器验证或最终 50 小时曲线。更没有验证拟议的“初级价目限开放”和“供应链免日限”，两项尚未写进游戏代码。按同一余额继续推算：下一村庄需 10 地契，缺 6，至少还要“卖资源→买地契”两笔，使共享计数到 4；再下一村庄需 11 地契，且初始 10000 木仓容使单笔木材出售最多换 10 地契，现有 5 次日限只能再成交一笔，随后必须等本地日界。这说明当前日限确实会成为隐藏的主线节拍，即使首笔续供可达。

## 实施验收与风险

真实实现回归须覆盖：无战斗新档 30 地契→4 级村庄→`sci_copper`→市场→卖木／买地契→第 5 级，且 `sci_coin` 与铸币厂仍未开放；未建市场、市场建造中、未研究和高级价目提前调用 `exchangeResource()` 全部失败且状态不变；初级供应链反复成交不吃共享日限，普通价目第 6 次同日失败、次日可用；所有汇率环路无套利；来源不足、目标仓满、非有限数量、备份失败、主档写失败均不扣费、不虚报成功；旧档、合法 0 值、刷新和离线恢复保持进度。VM 模拟只算逻辑回归，UI 入口与按钮还须真实浏览器冒烟；50 小时零战斗和有战斗路线应在桥接代码稳定后重新推演。初级市场使资源工人可在货币科技前产出金币，是有意的经济桥接；是否过快需用真实多路线曲线而非本单样本调整汇率。
