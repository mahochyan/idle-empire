# 早期战败补兵与同关重试（P111，2026-09-25）

- 对应权威设计：[《策划文档.md》§8.4、§8.5、§8.9](../../策划文档.md)
- 探针：[P111战败恢复驱动](../../tools/verify/probe-population-defeat-recovery-p111.js)；它调用[首战与补兵探针P102](../../tools/verify/probe-population-first-clear-replenish-p102.js)中的真实游戏函数。
- 原始结果：[连续与短时战败恢复数据](reports/data/p111-population-defeat-recovery.json)。
- 存档：P101真实新档零胜场路线经`save()`序列化，再由P102使用`loadSaveAndApply()`重载；仅使用隔离开发harness，不读取或写入玩家浏览器存档。

## 复放方案

连续路线和每600在线秒离线8小时的短时路线都从新档到18人零胜场保存，再准备相同的首战部队并回放普通关。两路在固定随机值0.5、0秒／胜补兵等待时均于第6关首次战败。失败后保留该关，记录战损与人口，用真实`train()`把步兵／猎人／青铜刀盾兵补到15／13／15的目标编成，推进600在线秒，再用实际战斗函数重试第6关。

短时路线继续P110的同一累计时钟：人口终档4188在线秒／172800离线秒；军备准备在4200在线秒先离线8小时，首战前累计到4411在线秒／201600离线秒；战败后的600秒恢复在4800在线秒再次经过保存检查点并离线8小时。

本样本中，战败前与战败后村民数相同：普通奖励路线维持18人；战后扩容敏感度路线维持19人。失败会损失参战士兵，却没有回退已获得的人口。三种分支都成功重排三类补训并赢下同一关；连续600秒恢复时，猎人数量和部分青铜队列尚未回到目标，但固定战斗样本仍可获胜。短时路线在600秒内经过一次真实8小时离线结算，动态队列和库存使三支都在重试前恢复到15／13／15。

## 设计含义与边界

1. 当前早期样本支持把“村民/住房成长”和“战场人数”分账：战败损失兵力，人口继续保留；恢复循环由资源、岗位、训练队列、在线tick和离线结算承担。关卡失败不应清空村民成长。
2. 这里的600秒是一次固定补训等待，非最短恢复时间或推荐的正式数值。金属岗位分支连续路线未补足目标兵数仍能通过，说明不能把本样本的通过结果当作完整军队恢复；后续还要比较战损强度和更高关卡。
3. 固定随机值0.5、单一早期编成和第6关单次重试不代表真实胜率。短时调度假设用户在会话窗口结束后关闭游戏；没有模拟操作耗时、浏览器暂停或实际设备计时。
4. 本批只给P102开发探针增加可选的战败后补训／重试路径；不修改玩家战斗、人口、奖励、存档逻辑或配置。
