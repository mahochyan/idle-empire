# P207：猎风弩骑射程与暴击的隔离实战比较（2026-09-26）

**历史候选提示：**本报告在能力修复前的源码上做隔离四模式比较；双能力候选随后由正式代码从同一实付档逐项复现，见[P208](live-cavalry-formal-p208.md)。下文“现行”指P207执行时的旧规则。

**结论：补齐配置所写的能力会改变第29关战果，但两项能力叠加的结果并不单调。** 在 P201 的73人实付战前档、固定战斗流1中，现行规则3回合全灭；仅补射程以54人战损过关，仅补10%暴击以48人战损过关；两者都补仍在第4回合全灭。后者不是“能力削弱”的证据：猎风在这一流实际暴击0次，仅补暴击的胜局也暴击0次，额外随机抽取已足以改写后续攻击顺序与战果。此比较只检验**猎风弩骑**在**远征第29关**的现有编队，不代表全部骑兵T2，也不据此修改第29关敌人数。

[探针](../../tools/verify/probe-live-cavalry-abilities-p207.js)以[P201 原始数据](reports/data/p201-live-cavalry-third-chapter.json)中固定流1、15到第29关前的完整 `rts_save` 为起点，逐字校验 SHA-256：`ecec78193a69954510eaac3827bb9b5e2b8323691e9f08dbadb3571086f43e5f`、`4cac51b4725c1efdea6b87017d09f38c0acef560ec1058e840b6ee95a8f9984a`。两档已实付解锁并训练15名猎风弩骑，均有73名现役；按真实编队操作上阵前排15铜卫／15猎风弩骑／15民兵T1，后排13＋15游侠T1。猎风**仍在前排**，没有凭候选能力移动位置或扩大编队；远程主要改变可选目标，也会经过现有克制关系。两份存档资源不同，尤其战前粮食分别约2.84、3.44；每次比较从原始档独立加载，不补兵、不注入资源或精魄。第29关敌阵经与 P201 比较未变。

四个模式在各自隔离 VM 中运行：现行；仅让 `isRanged('cavalry_wind')` 返回真；仅在猎风攻击时增加一次10%暴击抽取、通过原生 `finalizeCombatDamage()` 完成翻倍；两者均补。其余配置、存档、阵型与随机流一致。每场都调用真实 `loadSaveAndApply`、编队操作、`openBattle`、异步回调、`endBattle`、`exitBattle`、`save` 和重载，保留战后资源、队列、完整存档及 SHA。候选仅为 VM 中的行为包装，不是正式补丁；尤其暴击包装会额外消耗随机数。现行模式在两份源档各自原流重现 P201 的胜败、回合、战损、奖励、战功与精魄。
