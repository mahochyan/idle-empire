# P165：第3关首胜“拓居令”本地候选与复查（2026-09-26）

## 本次决定

按[人口与关卡成长接口P124](population-level-reward-design-p124.md)唯一给出数值的早期候选，在第3关首次胜利**结算后**发放6地契，战利品显示为“拓居令（地契）”。名称服务开局的边境开拓主题；内部仍使用现有`deed`资源。奖励不直接生成村民，也不回填刚结束的战斗。第4关以后没有照搬旧方案填奖励表；市场购契与自然出生继续承担零胜场人口保底。

这是可在本地复测的数值候选，不是已校准的全关卡奖励曲线。P102的特定18人口样本在L1–L3额外注入每关1地契，再在L3追加6张，合计9张才立即支付下一档扩建；当前代码**只接入L3的6张**。从18/18、地契0的同类档胜L3后仍缺3张，必须经市场等来源补足，不能把P102的即时19人口当作当前收益。尚未证明改善L6、L7–L10、战损或整体时长。母本没有普通关通用首胜地契表，我方本次处理属于章节结构适配。

## 实现与存档边界

`levels.js`只给L3配置`firstClearReward:{deed:6}`及显示名；`math.js`仅在普通战役胜利且关卡ID不在`S.defeated`时，调用现有`creditResourceReward`并在战利品中显示实际入库量。奖励和首胜记录在同一次`save()`中写入；主档或自动备份失败时沿现有结算快照回滚。资源满仓时按现有上限截断，首胜仍计入已通关。

存档继续使用`rts_save` v31，未增字段或迁移。既有旧档若已记录第3关胜利，重战不会追溯补领；未通关旧档可在首次胜利时领取。关卡选择页尚未预告该奖励，玩家目前只在胜利结算看见“拓居令”；UI美化由另一项工作处理，本批未碰`index.html`、`ui.js`、`sprites.js`、`visual.css`或资产。
