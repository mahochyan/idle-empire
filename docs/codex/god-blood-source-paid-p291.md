# P291 神域胜利血剂来源与净化剂实付

## 文档目标、代码现状、本次决定

《策划文档》要求发展副本承接《放置时代》的材料与成长回流，100 关仍是全科技后通关的陡峭主线。P289／P290 已用稀有市场的血剂完成两次净化、两次固定种子核心战及纳米甲 10→11 级实付，但“只能等市场买三枚血剂”的推断遗漏母本神域胜利来源。本批按母本解包源码补齐血剂来源，不改核心战斗难度、市场权重、刷新周期或 UI 美术。

母本本地 `210(1)_unpacked/_analysis/deob_main.js` 的 `winGodWar` 对六条神域胜利以 `per10000(10000)` 发放 `180001`「麒麟凝血丹」，按**本次胜利后**的警戒值分档：小于 2001 发 1、2001～4000 发 2、4001～6000 发 3、6001 起发 4；源码后续还按科技等倍率放大。`entities_table.json` 中市场 `380000` 每 1200 秒抽 10 格，`380009` 血剂、`380049` 净化剂保持原价和权重。科技 `460020`「贸易精通」影响上架货品的**可购买次数**，没有证据表明它缩短刷新时间，故撤回 P290 报告末尾“市场加速”这一待查方向。母本郊外采集及外域另有稀有血剂来源，本批尚未映射；源乘数也未接入，不能把当前四档称为母本全奖励公式。

本项目沿用已定的主题名「圣兽血剂／镇域净化剂」。`config.js` 将机巧遗迹及五条神域材料战设为每胜基础发 1 份血剂，`math.js` 的真实 `materialDomainEncounter` 按胜后警戒值计算四档数量，通过既有战斗结算、存档写入及失败回滚路径发放；`ui.js` 六张挑战卡预览本次血剂数量。没有新增存档字段，`rts_save` 仍为 v32；旧档中零血剂仍按既有迁移和默认值处理，历史超上限库存不裁剪。市场购买血剂继续可用，血剂兑换净化剂的价格仍为 3。

## 实付账本与边界

从 [P290 只读实付终档](reports/data/p290-second-core-nano11-paid-save.json) `e656589c007c1b48a68503567ef43ae65e17e4c8884b27d2841fe7750d920d06` 出发，在隔离 VM 调用真实材料战、异步战斗回调和市场动作。353 名出战兵以固定战斗种子 1 连胜「光学拟态机」三次，三场均无战损；其独立警戒值 0→100→200→300，血剂 0→1→2→3。随后按市场固定随机流 291、每次 `offlineAdvanceSec(60,1)` 推进倍率 1 的动态生产和补货；累计 30,000 个**模拟生产秒**后见到净化剂货架，实扣 3 份血剂购买 1 剂，金铸币没有用于购买血剂。金铸币因同期岗位生产由 1201 增至容量 10000；高能核心仍为 43，士兵 353，血剂 0，净化剂 1。终档独立重载一致。

[逐步账本](reports/data/p291-god-blood-cleanser-paid-report.json)、[可重载终档](reports/data/p291-god-blood-cleanser-paid-save.json)和[复跑探针](../../tools/verify/probe-god-blood-paid-p291.js)记录该路径；终档 SHA-256 `820721bd21fd33867a95dbb58fbae97a429dd9e67d576d934e893055351a6f16`，两次复跑一致，P290 输入哈希未变。此样本只证明一种不花金铸币买血剂的**有价转换**通路；30,000 秒来自单条市场随机流且人为指定离线生产系数 1，不是现实离线时长、平均等待或玩家节奏。三场战斗固定有利种子、无战损，也不代表后续高警戒稳定胜率。本批未使用新净化剂、未补兵复战核心、未通过觉醒第 7 阶；纳米甲 11→12 级仍缺至少 85 核心及相应战斗成本。P289／P290 存档和结果是补齐此来源之前的历史版本证据，按当前奖励代码复跑旧探针会产生不同血剂库存与输出哈希，不能用旧时长估计当前材料路径。
