## 最小可实施的玩家行动链

沿现有郊野猎场胜利取得六类心材 → 在边贸行刷新并付款买Ⅰ阶图纸 → 边贸行达相应等级、抽到Ⅱ–Ⅴ阶货位 → 消耗**库存**Ⅰ阶图纸按当轮品质价格换取一张高阶密卷 → 使用高阶密卷，永久累计对应百分比 → 知识仓真实增长后继续付 `upgradeEraStorage('quantumKnowledge')` 或后期单笔研究。每个箭头须由实际动作函数完成并单独保存；已使用的Ⅰ阶图纸不能倒扣来换高阶。玩家名沿本项目主题可用「星图密卷Ⅱ／圣界密卷Ⅲ／遗神密卷Ⅳ／渊海密卷Ⅴ」，内部键可用 `storageScroll2`–`storageScroll5`，避免把源名和未实现遗物直接显示为已获。

建议把 `CFG.beastExchange.highScrollTrades` 配成四个显式项：`{level:30/40/50/60,weight:20/10/10/10,firstScrollCost:3/4/5/6,capacityPerUse:0.015/0.02/0.025/0.03,useLimit:500}`；四种新 `CFG.eraMaterials` 各 `max:1000`。品质仍复用现有 `rollBeastOfferQuality()` 的 100/80/50/10%，价格 `ceil(firstScrollCost*quality/100)`；不再乘边贸行等级。交易消耗一个当轮货位，库存转移和进度只计一次。新增高阶货位要占 `offerTotalWeights` 中现有**未实现**抽位，维持总权重与六种Ⅰ阶、铭石、勋章和兽皮货位的边际概率；直接增大总权重或覆写已有货位会让前中段供应暗降。为了保持既有固定种子序列稳定，可在现行已映射货位之后从空抽位投影高阶权重；这与母本的货位排列顺序不声称逐种子相同。

`masteredCapacity()` 延续目前顺序：基础建筑/精通 → 蒸汽、电力、星核、量子仓研 → 星阵知识加成 → 五阶图纸已用数的**加法百分比总和**，而不是逐阶相乘。货币仓保持排除。实施只需在当前边贸行卡片加四档可见库存、已用数、当轮货位/价格和兑换/使用按钮；低于对应边贸行等级且无历史库存/已用记录的档位隐藏，符合现有未解锁隐藏约定。这个 UI 变动应局限于 `ui.js` 的边贸行块，不碰并行代理正在美化的 `index.html`、图片、3D 或全局布局。

## 数值付款接缝与上界

以 [P400 实付兵装终档](reports/data/p400-armament-natural-invested-save.json) 为单一观察起点：v34、边贸行 Lv79、Ⅰ阶库存0／已用133、`quantumKnowledge=7`，知识仓 `5,129,430,221`，星阵槽未开；六类心材库存合计711，当前只有两处Ⅰ阶货位（铁甲龟壳1份品质80、铁脊蜥龙筋1份品质50）。这些是现货，不是高阶密卷已取得或即刻大量可兑换。由当前真实 `eraStorageCost()` 与 `resCap('tech')` 在**只替换候选仓研等级**的隔离计算得到：7→13级下一笔费用分别 40／45／50／55／60／65 亿，付款前仓容逐级约 51.29／54.31／57.33／60.35／63.36／66.38 亿，均容纳下一笔。到 13级仓容 `6,939,817,357`，14级需单笔 **70 亿**，缺 `60,182,643`。若当时真买并用一张Ⅴ阶密卷，条件仓容约 **70.29 亿**，足以越过这一单笔墙；它仍须先真实取得名义 6 张Ⅰ阶（折扣时最低1张）与Ⅴ阶货位，并真实攒满70亿知识。此处没有向 P400 存档写入任何卷轴。

以 P400 当前 7级仓研、Ⅰ阶已用133且不增加建筑/圣阵为固定条件，Ⅱ–Ⅴ各用满500时知识仓约 **1,041.96 亿**，在数学上可容纳源 `450924` 的1000亿单笔门；四档新增2000张高阶密卷按100%品质的名义消耗 **9000张Ⅰ阶**，若每笔恰为10%品质则理论最低 2000 张Ⅰ阶。此为**条件上界与费用范围**，不证明货位、郊野心材、战损和实际时间能支撑2000次高阶交易，也不证明3000万勋章已得。Lv79源类权重口径下Ⅴ阶货位单抽 `10/680`，14抽至少命中一次的理想概率约18.7%，不是保底；再叠Ⅰ阶材料与货位供应，不能把条件容量写成已闭合成长曲线。

## 存档接线与最小验收

当前主档 `rts_save` 为 v34，`save()` 在 `math.js` 手选 `S.items`、`S.beastExchange`；`validate` 严格拒绝未知道具/交易状态键，`load` 最后整体赋值到 S。新增四档库存、已用计数、四档货位/品质时要升 v35 并同时改新档默认、序列化、v34及更旧档候选迁移、严格校验、保护副本、导入和保存失败回滚。对 v34 缺失字段填 0/无货位；合法0不被 `||` 改写。`storageScroll` 与旧 `scrollUsed` 原数保留，历史超仓库存或原已用数不裁剪；拒绝未知未来版与畸形高阶计数，失败前不得改运行中 S。关闭功能时保留所有库存及已用记录。现有 `refreshBeastExchange()` 使用浅拷贝回滚：新货位状态应整体替换对象而非原地修改旧嵌套对象，或改为深拷贝，保证写档失败时货位原状恢复。
