# P166：第3关首胜奖励与无奖控制的同源住房复查（2026-09-26）

## 本次决定

保留当前第3关首胜“拓居令（地契）”+6作为早期住房加速候选，暂不扩大到其它关卡或调整数值。P166在同一真实18/18人口、0地契、0胜场新档完成军备准备后，证实它能在一个固定市场策略下缩短到19、20人的在线模拟时间；尚无证据说明它能改善后续战斗胜负、战损补回或完整时代难度曲线。自然出生与零胜场市场扩容仍是人口保底路径。

## 方法与可复核结果

开发探针[probe-current-first-clear-population-p166.js](../../tools/verify/probe-current-first-clear-population-p166.js)先复用P101真实人口存档与P102真实建造、研究、训练、岗位分配动作，只取P102的战前序列化存档，**不执行**其历史`clearReward()`手工地契注入。战前档为tick 5815、18/18人口、0地契、36名军队。两份隔离VM以固定`Math.random=0.5`真实调用编队、`openBattle`、战斗回调和结算，控制组仅在VM内取消L3的`firstClearReward`。L1–L3两组胜负、回合、战损、非地契资源和tick相同；L3战利品显示及地契余额分别为“拓居令”+6／6张与无显示／0张。L3原生结算存档重载一致。

L3后采用同一开发侧操作策略：石料达到1100才用真实市场一次卖1000、至少保留100石；只购买每次扩村缺少的地契，调用真实`upgradeSettlement('village')`，在线`tick()`到自然出生，并把新增居民分配到石岗。每档再次保存并重载。时间从同一战前档tick 5815累计，单位为**模拟在线tick秒**；战斗异步回调的墙钟耗时未计入。

| 检查点 | 当前L3 +6 | VM内无奖控制 |
|---|---:|---:|
| L3结算后地契／下一扩村费 | 6／9 | 0／9 |
| 到19人需购契／花钱 | 3张／300金币 | 9张／900金币 |
| 到19人卖石／累计在线秒 | 2000石／125秒 | 6000石／525秒 |
| 到20人第二档需购契／花钱 | 10张／1000金币 | 10张／1000金币 |
| 到20人累计在线秒 | 683秒 | 1026秒 |
| L3结算至20人最低粮 | 268.3043 | 268.3043 |

因此此样本的首档住房省600金币和400模拟在线秒，到20人累计省343秒。18→19并非“胜L3立即送人”：胜后仍差3张契，要先卖料购契、扩村并等待自然出生。两支战前起最低粮都只有4.9599；军备入口本就贴近缺粮，不能把L3之后的268.3043解读为全程余粮宽裕。完整逐笔交易、存档摘要、战斗行和输入SHA见[原始数据](reports/data/p166-current-first-clear-population.json)。
