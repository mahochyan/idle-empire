## 3. 设计（数值均为【示例·待推演】，推演脚本通过前不得定稿）

### A1 分段斜率升级成本
- 实现点：`upCost()` 的倍率行（math.js@690）。
- 方案：`倍率 = upCostLv^lv × 分段系数(lv)`，分段系数表进 `CFG.curve.costSegments`：
  `lv≤9 段 ×1（保持现有手感）→ 10-19 段 ×3 → 20-29 段 ×6 → 30+ ×12`【示例】。
- 效果：保留各建筑自身的 upCostLv 差异（1.1~1.7），叠加"10 级墙/20 级墙"；升级时间仍线性 120s 封顶不变。
- 存档影响：无（纯计算函数）。

### A2 免维护带
- 实现点：`totalUpkeep()`（math.js@304-311）。
- 方案：`CFG.curve.freeRation = {base:10, perBarracksLv:2}`【示例】→ 免维护额度 = 10 + 营帐等级×2；按**全军总数**（池+远征+驻军合计）先豁免 N 只，超出部分逐只计费（对齐《放置时代》≤200 兵免军粮的"按总数"口径，Q3）。
- 效果：新手期白嫖安全区（对应序章 0-3h 爽段）；扩军后进入"卡"段。
- 存档影响：无。

### A3 资源转换阀
- 实现点：新增 `exchangeResource(key)`（math.js 逻辑层）+ UI 卡（ui.js 设置/建筑页）+ `S.daily.exchangeLeft`。
- 方案：`CFG.curve.exchange = [{from:'wood',to:'stone',rate:0.7},{from:'stone',to:'food',rate:0.6},{from:'food',to:'wood',rate:0.5}]`【示例】＋每日 5 次上限【示例】；取整 `Math.floor(给×rate)`，受存储上限钳制；失败明确提示。
- 效果：溢出资源有出口（治"资源沉没"），汇率即官方调控把手。
- 存档影响：新增 `S.daily`（见 §4）。

### A4 每日硬上限与日界
- 实现点：garrison.js 入侵触发处加计数门（warning 触发前检查）；`S.daily.invasions`。
- 方案：每日驻军入侵上限 5 场【示例】＋自然随机 0~2 场（超限当日不再触发 warning 并提示"今日入侵已结束"）；日界＝本地日期（YYYYMMDD），每日首个 tick 检测切换并重置计数。
- 效果：把随机计时器改为"固定日课+少量随机"，制造回访节奏（策划 A4/D5 思路，签到本体留后续单）。
- 存档影响：`S.daily` 持久化。
