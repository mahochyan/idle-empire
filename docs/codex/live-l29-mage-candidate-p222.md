# P222｜第 29 关 `[11,8,5]` 法师候选的真实 Edge 隔离复核

结论：在现行战斗代码和本批冻结的 Edge 视觉版本中，只把测试页面的第 29 关法师三团人数临时改为 `[11,8,5]` 后，P217 现行配置下全损的逆序阵固定流 8、9 分别胜损 64、62 人。每流的 Edge HD2D、Edge 视觉回退和加载**同一浏览器战前完整档**的 Node VM，首回合、随机轨迹、结算、奖励和仅去 `ts` 的完整战后存档逐项一致；胜败、逐兵种战损、敌余 HP、随机次数、实入资源等也与 P218 对应 Node 隔离候选一致。候选没有写入正式 `levels.js` 或存档，不能据两条固定流推定玩家胜率或第 29—31 关曲线已平滑。

## 输入与隔离方式

当前 `master`，HEAD `406bce4dc86a7d12f442ceebe5143ec9fa6f6e6d`。输入是 P201 `t2SecondBack73` 来源流 1 的第 29 关实付 73 人完整战前档，原文 SHA-256 `ecec78193a69954510eaac3827bb9b5e2b8323691e9f08dbadb3571086f43e5f`。Edge 经页面战斗页和编队弹窗合法排成前排“民兵 15 → 猎风弩骑 15 → 青铜刀盾兵 15”、后排游侠 13＋15，逐项核对库存、资源、队列、槽位与现行第 29 关敌阵，保存重载。流 8、9 新形成的战前完整档 SHA 为 `2a7e6986258ca50b95c67619bc3d4c28006b382cae7f6d1c1f5b2fce01036fea`、`adc1788bbf5a41dcfb74cb1bbbe6ac0e58c9863759fee0d93c60db2b2fbecdc6`。与 P217 来源流 1 的正式配置战前档对比，差异仅是 `ts` 和新编队槽位的 `id`，兵力及资源等业务状态相同。

每场从该流同一战前档重载，先在页面中核对正式敌阵法师 `[13,10,6]`，然后只赋值 `CFG.enemies[28].units.mage_t1=[11,8,5]`。探针把其余整个敌阵对象与正式值逐项比较，且当场验证 localStorage 存档原文未变。HD2D 场按正常页面挂载；回退场仅在隔离页面使 `HD2D.mountBattle()` 返回 `false`。两场都通过页面按钮设 4 倍速并用正式异步 `selEnemy(28); openBattle()` 结算。Node VM 在从同一浏览器形成的档加载后，仅做相同的临时 CFG 赋值，再调用相同战斗入口。战斗后 Edge 页面再次完整重载，四场均看到正式 `[13,10,6]` 恢复，存储的战后原文未被重载改写；候选没有持久化。

测试为旧档加载阶段冻结档内时间戳，加载后恢复时钟，暂停背景 `setInterval(tick)`；战斗 `setTimeout` 未替换。随机流沿用 P201/P217/P218 的 xorshift32 `(flow*1009+29*9176)>>>0`，开战时抽取次数均为 0。未注入资源、士兵、胜利、科技或奖励；没有在正式文件中改敌阵。
