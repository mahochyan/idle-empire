# P244｜边疆铜点固定400铜钱：正式结算、实码回放与复查

2026-09-27。本批为第二条「拓境远征」的首个边疆铜点增加每次**真实胜利**固定400铜钱。铜点等级、胜次、钱币和战损由同一场 `endBattle()` 的同一次 `save()` 保存；钱币按现有专仓容量实入，结果显示实际获得数。未修改100关、出生率、地契价格、铁点、外域或UI美术。玩家页面尚无该区域按钮，因此这仍是可调用的区域后端切片，而非完整可见的第二套副本。

## 定价依据与实际结果

[P239](development-border-battle-p239.md)完成首个铜点战斗后暂不发币；母本铜敌`560005`的`Get`给出400钱币静态基数，但警戒奖励倍率及我方市场、地契、住房、粮食和仓容不同，不能直接认定母本动态收益适合我方。[P240冻结四臂试价](border-copper-economy-p240.md)在同一18人口、零主线胜场的实付早期档，以16个相同随机种子和当前真实市场／购契／扩村／自然出生／调岗／训练动作，比较0、固定200、固定400、母本警戒映射四种铜点钱币。0臂也允许卖资源购契。

| 每胜钱币策略 | 第20胜平均人口 | 前20胜平均补兵等待 | 各流最终人口 |
|---|---:|---:|---:|
| 0，仍可市场购契 | 21.25 | 3998.7模拟在线秒 | 22–23 |
| 固定200 | 23.875 | 3227.8秒 | 24–26 |
| **固定400** | **26** | **2766.3秒** | **27–29** |
| 母本警戒映射 | 32 | 2516.4秒 | 33–40 |

固定400比0臂在第20胜平均多4.75人口，前20胜少等约1232秒；母本动态映射再多6人口，却只再少等约250秒。四臂在同一固定军备策略下均为合计430胜／442战、只有4/16流到第30胜，首次失败在第23–30场；更多人口未在该试验中提高单场军力上限。四臂训练付款后最低粮都接近零，钱币无法直接当作粮食保障。故选固定400作为**首个运行版试价**，不叠警戒倍率或直接送村民，后续仍需多策略与长期区间校准。

正式实现仅把`config.js`首个铜点的`reward.coin`设为400，并在`math.js`的区域真胜分支调用共享的`creditResourceReward('coin', e.reward.coin)`；已有专仓、历史超仓保护、一次性结算与保存失败回滚继续生效。没有新增存档字段，`rts_save`仍为v32，v31及更早档沿P238保护迁移；旧铜点等级、库存、主线成绩不清零。满仓时界面显示实入数而非名义400，已超仓的旧档不会被该场胜利裁剪。败逃、伪胜、重复回调不发币；写盘失败恢复场前钱币、点位、编队和日志，主档原文不被伪成功覆盖。

本批运行代码修改为`config.js`、`math.js`两处；`tests/progression/development_border_v32.js`与`development_border_browser.js`增加正式奖励、仓容和刷新断言。新增P240/P243/P241/P242开发探针、逐场数据及报告；更新根目录`策划文档.md`、实施台账与P228/P239历史报告的后续状态。没有编辑并行UI任务正在处理的`index.html`、`ui.js`、`visual.css`、`sprites.js`或美术资源。

[P243当前实码回放](border-copper-economy-actual-p243.md)在正式`config.js`和`math.js`上只观察奖励调用与战斗保存，不再由探针注币，重走P240固定400臂。16/16流的逐胜人口、胜数、实际收益、市场交易、补兵费用与等待一致；战斗结算及补兵后的两类存档哈希也16/16流完全相同。430场真实胜利的钱币在点位胜次同一次保存中恰好入账一次，主线成绩未变。P240探针绑定实装前源码指纹，**不得**在已发币代码上重跑其注币包装器，否则会人为重复发奖；现行复查只运行P243。
