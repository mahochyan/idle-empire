# P145：短时战役战后离线食物账拆分（2026-09-26）

## 目的与方法

P112当前工作区复跑在战后请求28800秒离线时，只推进6574秒。P145复现同一条顺序扩建零胜场人口路线，并把其真实`save()`终档交给P102，通过当前真实关卡、训练队列和`settleOffline()`继续；在隔离harness里仅包装真实`processQueue()`与`productionSecond()`，逐秒记录真实队列扣粮、农田产出、居民口粮、军队维护及生产链对粮食库存的影响。探针在首个被食物截断的离线窗停下，不写玩家浏览器存档。

此样本从P101人口路线的4320在线秒、201600离线秒保存点继续，入口18/18；固定P102随机值0.5，profile为每600在线秒后请求8小时离线。截断发生在第4关胜利后的tick边界，此时该战斗支线已自然到19/19。

## 结果

| 项目 | 实测 |
|---|---:|
| 离线请求 / 实际推进 | 28800 / 6574秒，`truncated:true` |
| 离线前粮食 | 56.293556 |
| 成功步结束粮食 | 0.001395 |
| 6574秒农田产粮贡献 | +19524.780000 |
| 居民口粮（19人） | −7494.360000 |
| 部队维护（随补兵队列动态变化） | −10286.712161 |
| 补兵队列直接扣粮 | −1800（期间训练完成6名青铜守卫，队列尚余2名） |
| 金属生产链耗粮 | 约0 |
| 实际粮食净变化 | −56.292161 |

账目闭合：`56.293556 + 19524.780000 − 7494.360000 − 10286.712161 − 1800 ≈ 0.001395`。第一个失败候选秒没有再扣训练费；其农田贡献为2.97粮，居民口粮1.14、部队维护1.840683，候选余额从0.001395变成−0.009288，离线结算因此回滚这一秒并停止。也就是说，这个样本不只是一次性补兵扣粮：队列支出把开窗储备几乎耗尽，而补入部队后的下一秒维护已略高于当前农田产出。

## 设计含义与边界

这条样本不支持提高村民基础出生率，也不支持把人口口粮或军队维护整体降价。首先应把“待训练兵种的直接粮食费用”和“完成补兵后新增部队的持续维护”一起纳入短时离线可支付预算；单看当前粮库存或当前粮工数不足以判定8小时窗口能否跑完。可验证的规则候选是按目标离线时长模拟`农田产出 − 居民口粮 − 动态部队维护 − 队列直付 − 生产链耗粮`，并要求每个模拟秒库存不低于0，再比较调粮工、延后排队或补足战后储备的成本。该候选尚未经过多种人口/军队配置和在线间隔验证，不能直接变为全局规则。

P145原始范围仅是顺序扩建、固定随机值0.5的一个战后窗口。P112完整短时战役仍失败；P149已按同口径单独定位四学者路线的首个截断点，结果与本报告逐字段相同，但其余奖励/岗位分支和完整短时战役仍未通过。原P112全路线汇总只作历史快照。报告不修改玩家运行逻辑、CFG、存档字段、UI、美术或Android；开发探针只在隔离harness处理测试存档。

验证：`node --check tools/verify/probe-short-session-food-budget-p145.js`退出0；`node tools/verify/probe-short-session-food-budget-p145.js`退出0。该探针断言离线成功步数、首个拒绝步及分项粮食合计与真实结算净变化闭合。原始分项账及输入SHA见[P145数据](reports/data/p145-short-session-food-budget.json)；相关边界见[P112短时战役复核](short-session-strategy-campaign-p112.md)。
