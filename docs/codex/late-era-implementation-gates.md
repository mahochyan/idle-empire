## 先锁定的共用口径

- 设 `P(r,n)` 为节点 `n` 对资源 `r` 的**不可拆单笔实付**，`C(r,t)` 为付款前当前存档的容量，`B(r,t)` 为付款前库存。每个必须经过的节点都要在正常新档路线证明 `C(r,t) ≥ P(r,n)` 且 `B(r,t) ≥ P(r,n)`；不能用导入的超仓旧档、开发者加资源或后续时代才开放的科技来过前置。容量升级也逐级作同样的检查，并校验上一笔付款后还有供给路径，不能只展示满级终值。
- 每段的最低产出预算要用**资源单位／秒**与指定时间窗 `T_i`（秒）写出：`初始库存＋可重复净流入＋可重复战斗/交易收益 ≥ 本段所有必需付款＋军备/上游/维持消耗`。这个总量不等式只是必要条件；还必须按建造完成、缺料停产、满仓、付款、人口增长、粮耗、训练和离线事件的真实顺序回放。`T_i` 由全时代内容表和 50 小时总内容目标再分配，不能把旧文档的 0–3/3–15/15–50 小时示例直接设成关卡时钟，更不能承诺 50 小时神话毕业。
- 勋章若来自战斗，按**每次可重复胜利的实得、胜率、战损、补兵与主动操作时间**算吞吐；随机市场和稀有材料只能在已验证出现频率、购买次数及等待分布后计入主线。纯本地、无 VIP、无广告的均衡路线必须能到达；零战斗路线至少要维持人口、粮食、知识和工业生产至第一个**明示的**必须战斗门。重经济、重军事和短时上线/离线另测，不能把离线 `0.6×` 当全局产量常数。
- 每批以「前置研究→原料/工人/人口/粮→当前容量→建筑/科技逐笔费用→净产率与时间→可持续军队→敌人/首通与重复奖励→下一面墙」八栏出一张事件账本。UI 同源显示锁定原因、当前库存/容量、毛产、原料与口粮消耗、净产、翻墙收益。旧档要保留超仓库存与已解锁进度；新字段验收 `rts_save` 序列化、迁移、备份失败保护、离线和重复操作，战斗/驻军共享计算仍需双路径核对。

**当前我方起点（工作区静态核对，非后期运行结果）：**`config.js` 只有木、石、粮、科技点、铜、铁、金币、地契；无煤、金属银/金、钢、母本勋章资源及后五时代树。`CFG.tech.longLadder` 当前启用 8 个 `sciencesLong` 节点，`sciencesNoMerit=true`，`S.merit` 是现有战功，不可未经设计就当作勋章一比一代用。`resCap('tech')` 取启用的 `CFG.caps.expand.res.tech={max:3000,maxPerLv:2000}` 加学院等级；`ownMax.science=50`，故**按现公式及上限计算**最高 `3000+2000×50=103,000`，还未证明学院 50 级从新档可达。这刚覆盖参考蒸汽的 100,000 单笔费，不能覆盖电力的 5,000,000。P03 已完成的实际人口、地契续供与 v4 存档是早期基础，不等于后期资源/军备闭环；见 [`implementation-progress.md`](implementation-progress.md) P03。上述事实会随并行工作区改动变化，实施前须重新取基线。

## 不应原样搬入我方的数值与捷径

1. **研究标价和上限同时照搬。**现有科技容量理论最高 10.3 万、钢尚不存在；直接填 500 万/1 亿/30 亿/10 万亿只会制造容量死锁。先用我方真实资源命名、建筑费用、满仓逻辑和跨级容量科技闭合每一笔，再定最终标价。母本 `getResourceMax` 的公共与四时代科研科技各满级 ×11，叠产业/卷轴后极值巨大；需对 JS 有限数、整数精度、显示缩写、存档校验与旧档超仓作边界测试，不能把极端满级乘积视为正常玩家曲线。
2. **基础每人产率、静态工人配方和幸福/季节一律乘。**母本钢是铁4＋矿4＋煤4→钢1/4000ms；我方当前铁吃铜3/秒且无煤、钢，食物口粮为 0.1/人/秒。先完成新原料拓扑与岗位人数预算，再校准时间。母本知识分支没有直接政策或季节乘区；幸福 150 在源码对应条件系数 110%，专属科研科技每级 5%，不能套旧报告的 112% 或把全部专属科技写成 10%。
3. **把所有勋章压成现有战功，或靠 VIP/随机商店补缺。**现有发展研究启用 `sciencesNoMerit=true`；母本后期数百万/千万勋章和交易所、市场、区域材料是不同来源。若合并资源，必须重新平衡当前兵种研究及原有战功收益/存档；若另建资源，需完整迁移与 UI。无付费广告加速、无刷不到指定货物的路线必须有可信完成时间；新增确定性兜底若超出母本，应标成显式改编并另审。
4. **把时代门当军备、区域与收益已经完成。**研究费用只买入场资格，装甲/电磁/宇航/未来战士还要三金属招募，装备与星级/武装有另一组成本。敌人生命在我方当前公式中参与伤害，不能把母本 Boss HP 或极端模式倍率直接复制；同一支军队的战损、训练、驻军、重复奖励要在数值账本里结算。蒸汽工厂名称、量子市场入口及研究 `Unlocked` 不能当持续产量已生效的证明。
5. **把 100 关均分十时代或把 50 小时当神话毕业。**《策划文档.md》§8 明确原有 100 关只是部分区域承载，神域/星域/旧日各有独立入口；旧 50 小时只指内容长度目标。时代间隔、短时上线体验和终局耗时须在全链费用、产速、容量、战斗难度与重复收益定稿后，由真实事件推演重新给出。

本稿的放行结论只有「各批应如何证明可达」，没有宣告任何 L0–L6 已通过。设计模型需先产出逐笔付款前/后快照、容量来源、净流量和敌人/材料收益；将来实际批次再用真实动作函数、存档迁移、浏览器冒烟与相同场景的离线/在线回归复验。撤回本稿只需移除此文件，不动现有生产代码或用户未提交改动。
