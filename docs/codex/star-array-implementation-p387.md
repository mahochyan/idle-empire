# P387｜星辉圣阵首版：研究、三石、槽位与秘典知识仓

日期：2026-09-30。开工 `master`、HEAD `5baef7d9edc4046aab247c542e0940bb8a49da7c`，保留并行美术与其它玩法改动，不建分支、不提交、不推送。本报告只覆盖星阵核心；同批星界兽域战斗与三石真实产出由并行改动单独验收。

## 文档目标、原代码现状和本次决定

[P364 源审计](star-array-source-design-p364.md)确认母本「星域异兽／核源星阵」分别为知识 2 亿／3 亿、勋章 100 万／200 万；20 个槽位的开槽、属性刷新、升级分别消耗三种星石，知识仓属性 `320004` 只有对应兵种觉醒 20 阶且至少 50 星时生效，乘区在拓仓图纸之前。原代码只有星核时代、量子时代及仓储倍率，`rts_save` 为 v32，没有星石、星阵状态或星兽材料入口。

本次以我方后期西幻主题命名为「星界兽域」「星辉圣阵」「星辉原石」「幻相石」「圣环核石」。两笔独立科技沿既有 `researchScience` 前置、一次扣费和写档失败回滚；量子研究的 30 亿知识／300 万勋章原价未改。星阵首版只实装可验证的**秘典知识仓上限**属性：每个槽位先以 `1000×(索引+1)` 圣环核石开槽，再以 `100×(索引+1)` 幻相石定向刻印知识属性，随后每级以 `20×(索引+1)×当前等级` 星辉原石升级，最高 10 级。未接 13 属性随机池、超凡变异及其他战斗属性；这属于我方首版适配，不宣称完整复刻母本。定向刻印避免玩家付费刷到未实装的无效属性。

星阵知识仓贡献为 `floor(Σ[开放且知识槽的 (4+2×floor(索引/3))×等级] × 觉醒星数系数)` 百分比；20 阶未达 50 星为 0，50／100／150／200 星的系数依次为 0.6／0.8／1／1.2（配置保留母本 250／300 星档，当前觉醒存档上限为 240 星）。`masteredCapacity('tech')` 在时代仓储后、拓仓图纸前乘该比例；既有超仓知识不被回收，满仓时停止新产出。星阵动作在函数层检查研究、索引、顺序、槽位结构、有限安全整数库存、战斗或历史离线结算忙碌态；UI 按钮只显示已开槽和下一待开槽，旧按钮的等级参数可阻止重复点击额外扣费。

## 存档兼容

主键仍为 `rts_save`，schema 升至 v33。新增 `S.starArray.star_trooper.slots`（20 槽，每槽 `open/type/level/refreshCount`）与三石库存，覆盖默认值、序列化、候选校验、v32→v33 迁移、显式应用与重载。已有 v32 档在独立候选中补零，迁移前原文写入 `rts_save_premigration`，备份或写入失败终止并保持主档与运行状态；v33 缺字段、非法槽位／物品和未来 v34 均进入保护，不能由 tick 或 save 自动覆盖。关闭界面或暂未获得材料不删除字段。**回退旧代码不能安全读取 v33 主档**；需要先导出并使用已保留的迁移前 v32 副本或做专门降级迁移，不能直接覆盖当前主档。

以 `docs/codex/reports/data/p386-300m-paid-save.json` 的 v32 实付档实际加载验证：状态为 `migrated`，迁移前副本与原文完全相同，知识、勋章、通关记录和觉醒进度未改，三石为 0、20 槽均未开，v33 重载 `ok` 且知识仓上限一致。这只证明兼容性，不证明自然路线已付清两笔研究或已获取星石。
