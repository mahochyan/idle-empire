# 人口与城镇扩容方案（设计稿，2026-09-23）

本方案对应《策划文档》§8.4 的人口、建筑、市场闭环。目标是让劳动力随经济发展扩张，关卡成为可选奖励与战力检验，不成为人口增加的唯一入口。数值目标是待推演的验收线，不冒充《放置时代》原始配置。

状态说明：下表“当前游戏代码”记录的是 P03 实施**之前**的事实基线。P03 已实现 0/4/30 开局、真实人口、三类聚落、v4 存档与冶铜市场早期续供；真实函数零战斗探针第 372 在线秒可扩到容量 9。按全部实际人口收取 0.1 食物/人/秒后，每小时集中操作一次的 50 小时在线样本为容量 311/实际 308，但需要 148 次扩容与 49 次买契，现有八项发展科技首小时内已全部完成，故长期难度曲线和十时代岗位预算仍需另行设计。以 [实施台账](implementation-progress.md) 和 [新曲线探针](population-curve-probe.md) 为当前代码与测试证据，不把本设计稿中的历史问题误写成仍未修复。

现状虽已不再要求打 Boss 升城镇，**经济上的硬卡仍存在**：当前第一笔地契的正常可见路径晚于完整的六步货币研究。生产结算修复前，一次按真实函数回放的新档无战斗策略在第 4675 秒（约 78 分钟）才升到 Lv.2，完成后 `popCurrent()` 又因累计 `S.tick` 足够长而立即从 10 跳到 20；这是特定策略的历史可达性证据，不是最短通关时间、浏览器实测或修复后重测。该正常路径只需一次金币→地契兑换；`exchangeResource()` 另有缺失市场/科技动作校验的旁路，不能拿旁路的更短时间当正常玩家体验。并且 10 人若安排木 1、石 1、粮 2、学者 1、铜 3、铁 1、铸币 1，已把岗位用尽；铜 3 人刚好支付铁 1 人每秒消耗的铜 3，无法积累铜，更没有调岗和扩军粮食余量。粮工按当前 2.25/人/秒、人口口粮和军粮反求。铸币耗粮在修复前的代码是 5/人/秒，与启用配置 1/人/秒冲突；本日线上/离线共用生产步已改读生效配置 1/人/秒，回归 10/10 通过。岗位预算要按修复后的真实净流量重新跑 50 小时，不使用历史误值调人口成本。

## 采用的结构

1. **人口容量由可重复升级的聚落建筑提供。** 用我方像素村落美术呈现村庄、小镇、城市三层扩容线；每级容量先按母本 +1/+2/+4 作结构基线。村庄从开局开放，小镇/城市由对应发展科技开放，城镇称号与时代美术可继续存在，但不再是唯一人口上限。地契是升级消耗品，不因为库存越多就自动增加上限；后续若做扩民令，应作为独立道具。
2. **启动地契与后续补给分开。** 新档先按母本提供 30 地契，让村庄的前几级建设在零战斗、零货币研究时就能进行；只有扩容建筑实际升级才扣地契。旧档需用一次性兼容规则处理，不把新档礼包反复发给已有存档。启动库存用完前，必须有可达的经济续供：优先沿用市场卖资源/产币→购地契；若现有末端 `sci_coin` 门让续供断档，则仅前置基础交易，不提前开放铸币和高级交易。保留买卖价差，核算所有兑换环路，防止套利。当前共享的“每日 5 次”不能限制主线地契兑换，否则多次扩容会变成跨日等待；主线交易另定次数或取消该限额，再以费率控制速度。关卡奖励可提供额外地契或资源，但不得成为必要条件。

   以母本村庄每级 +1、当前级为 0、折扣系数暂取 1 的示例，前四级地契价是 5、6、7、8，共 26；30 地契可把初始容量 4 提至 8，剩余 4 不够支付第五级的 9。实际折扣与之后的研究/交易时点仍需核对。这说明“开局送 30”只能解决起步，不能代替持续供给。
3. **实际人口成为存档状态。** 分别保存实际人数、上限来源、已分配人数、下一次增长进度；`空闲 = max(0,实际−已分配)`。新档按母本以实际 0 人、初始容量 4 人为校准起点；若我方保留现有 4 人开局体验，必须在曲线账本明确这一差异，不再声称完全同值。母本初始粮食 0 有默认农田启动；我方当前初始食物 300，因此若改为 0 人也不会立即断掉人口增长，未来若连食物一并归零，必须先实现无需人口的启动粮源。食品库存大于 0 时按每 10 秒基础 +2 人向上限增长，育政策以后再提供 +5/项。扩容只提升上限，不补发过去的十秒周期；粮食不足暂停增长并给出恢复提示。母本离线结算链没有按离线时长追补人口，因此最终对齐规则为**离线生产可推进，人口不离线增长**。当前离线结算推进 `S.tick`，派生式人口反而会随之增长；迁移时保留已形成的人口，再消除此口径冲突。粮尽死亡若要加入，另按母本规则和可恢复性验收，不能靠删掉已分配工人伪装人口死亡。
4. **劳动力预算先于研究费用定稿。** 每个时代把木/石、学者、上游加工、下游加工和扩军所需工人列出，再按“粮工产出 ≥ 加工耗粮＋人口口粮＋军粮”反求粮工数量；因为人口口粮也随工人数增加，须用实际净流量求解，不能凭固定的两名粮工估算。进入该时代前容量至少为必需岗位数的 `1.25 倍`，并至少留 2 个空闲岗位；这是候选设计验收阈值，最终由实际资源净流量、战损和 50 小时模拟修订。目标是玩家可以专精调岗，但不必为了维持刚解锁的产业长期停掉另一条必要主线。

| 里程碑 | 暂定验收目标 | 原因 |
|---|---|---|
| 开局→首次扩容 | 无战斗、无需末端货币研究；启动 30 地契允许首次聚落升级，实际人口按十秒节拍回填 | 母本礼包解决首笔地契；我方扩容费用、初始人口与回填时间仍需真实代码回放确认 |
| 铜→铁 | 铁研究开放前能自然扩到至少 14 人左右 | 当前铜 3 人仅够喂养铁 1 人；要有铜净结余、学者与粮食余量 |
| 铸币与交易 | 铸币研究开放前至少满足“持续产粮 + 学者 + 铜铁 + 铸币”的岗位预算，并留 2 个空闲人口 | 线上/离线铸币已按启用配置耗粮 1/人/秒；用实际净粮率、军粮与岗位需求定人口目标 |
| 后续时代 | 随新工种和效率乘区逐段计算容量与人口回填时间，不以现有 110 的固定终点代替长期曲线 | 十时代、50 小时目标需要数百级建设是否必要，由全资源链计算而定 |

## 实施与验收顺序

1. 先建立“启动 30 地契→前几级聚落→经济地契续供”和各时代的完整依赖图；核对地契费用、交易汇率、仓库容量、每日限额及可支付时间，确保不借助关卡、测试按钮或动作接口漏洞也可达。交易动作入口必须验证市场已开放、建成及相应科技，防止绕过界面锁直接换地契。
2. 再实现聚落建筑与人口状态，并提供旧档迁移。旧档用旧规则计算迁移时的实际人数，至少保留已分配人数和已获得的城镇容量作为兼容底线；不裁剪超额旧档，不把合法 0 当缺省值。解析和迁移在候选数据中完成，备份失败时不覆盖 `rts_save`。
3. 统一线上/离线生产与粮食消耗事件的顺序，人口增长只在在线十秒事件运行；离线恢复不能借累计 `tick` 追补人口，且不能回收已有的历史人口。界面直接显示“已分配/实际/上限、增长条件、下一级容量增量与资源缺口”。
4. 用真实实现跑零战斗经济策略、正常战斗策略、偏学者策略及离线策略的 0–50 小时回放；检查每时代首个有效工人、研究、加工、仓容、市场和战斗战力均可达。测试包括粮尽暂停、提升上限不追溯生人、重复交易/升级不重复扣奖、刷新存档、旧档不丢人、无套利和每日限额不阻断主线。

本稿先确定人口扩张机制和可达性原则；上表时间及容量是待模拟的验收候选，不是已生效的游戏数值。原创玩法继续放在完整母本路线完成之后。
