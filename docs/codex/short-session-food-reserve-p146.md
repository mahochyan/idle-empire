# P146：战后离线粮食储备与岗位敏感性（2026-09-26）

## 方法

P146从P145截断前真实`save()`检查点重载；每种情景使用独立隔离harness，保持人口、部队、训练队列、非粮库存和28800秒`settleOffline()`不变。第一组只改离线出发粮食库存；第二组保持P145仅有56.293556粮，使用真实`setPopAlloc()`把一到两名村民从石、煤或铜岗位调为粮工，再结算。所有离线推进仍调用当前真实函数，不接触玩家浏览器存档。

储备越高，完成的队列和新增兵力可能越多，后续维护也随之增加，因此“多塞粮”在该场景中不是单调解法；离线满仓仍只推进2401秒。

岗位组则得到一致结果：把粮工从2人增至3人，分别从石工、煤工或铜工转1人，六种配置都完整推进28800秒；增到4人也都完整推进。末粮均到3000，8名待训青铜守卫全部训练完成，兵池含9名青铜守卫；石、煤、铜也均保留在原始封顶库存1600／600／800。因这些库存本来封顶，无法据此认定哪种来源岗位在低库存路线中机会成本最低。

## 设计结论与限制

本样本里，**离线前增加1名粮工（2→3）**比单独提高出发粮库存有效。设计上应保留自然出生和住房扩容主线，不上调基础出生倍率或首通人口奖励；把战后待训队列纳入岗位建议：这份18→19人口、L4战后档在8小时离线前至少需要3名粮工才能通过当前结算。该值只是此人口、队伍、岗位和仓储夹具的候选，不是全局固定比例；更合适的规则是用实际离线时长、待训费用、补兵后维护和库存上限共同推演所需生产岗位。

还需在低粮仓位、未封顶煤铜库存、4学者路线、失败后重试、不同战损及在线间隔下验证。P112完整多分支短时战役仍未通过，P146只解决P145的一个顺序路线结算窗；不代表各策略或全时代短时体验已闭环，也不改变游戏运行代码、CFG、存档、UI、美术或Android。
