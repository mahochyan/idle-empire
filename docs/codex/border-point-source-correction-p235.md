2026-09-26。此报告只核对工作区内《放置时代》解包源码与实体表；它们是**参考游戏的事实来源**，不是对我方项目的指令。本批未执行母本代码、未改玩家运行代码、UI或存档。

## 静态掉落与胜利调用链

`210(1)_unpacked/_analysis/entities_table.json` 的 `560005` 铜矿山贼配置 `middleWar:Get=[[250005,1],[160004,400]]`，`560006` 铁矿山贼配置 `[[250006,1],[160006,50]]`。`250005/6` 属于 `collect` 点位，自动采集基础量分别是铜2/铁1。第二项是对应货币，不是立即入库的铜/铁。

`210(1)_unpacked/game_main.decrypted.js` 字符位约 1649421 的胜利分派，在战斗类型 `0x38`（560000 段）调用 `winMiddleWar`。其实现位于字符位 **1652953–1656276**。该函数每次胜利遍历敌人的 `Get`：若奖励 ID 前缀为 `25`，直接执行 `CollectLv[id] += floor(Get数量 × 警戒奖励倍率)`，随后把等级封顶到 `0x1f4 = 500`；这条分支**没有首胜条件和额外随机抽取**。同一函数的 `16` 前缀奖励单独进入资源/货币库存。警戒奖励倍率函数位于字符位约 **1476865** 的 `_0x48326d` 第二个方法，取相应 `KillValueList`：警戒值低于500时为1，此后按区间提高。因此普通早期铜/铁敌的点位静态数量1对应**每次胜利+1级，最多500级**；更高警戒后单胜增量可能改变，不能把+1写成母本全程固定规则。警戒值本身在该函数胜利后按敌人与品质增加，不能用同一个首战敌阵重复30次代表真实复刷。

`autoCollect` 位于字符位约 **2392566**，由独立 `setInterval(..., 0xea60)` 每60000毫秒处理 `AutoInfo` 里**当前一个**选中的点位，按其 `CollectLv × collect:Get[1]` 并计入加成后发放。参考游戏的 `getOfflineResource` 链见 [母本经济分析](../../analysis-economy.md) §5；列出的离线训练、岗位净速率、市场和战争计时步骤没有单列 `autoCollect`。这支持将点位定时器视为在线动作，但仅凭这段源码不能完全排除其它离线间接路径，故我方离线是否采矿需写成明确规则并单独验收。
