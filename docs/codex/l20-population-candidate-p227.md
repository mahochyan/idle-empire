# P227｜第20关首胜拓居令候选的同档实付承接

**本批只比较挑战线第20关的隔离候选，不改变正式100关，也不替另设的《放置时代》式发展副本决定人口奖励。**当前 `levels.js` 只有第3关首胜配置了「拓居令」+6；本探针在三个独立 Node VM 内分别保持第20关无奖、临时给首胜+11张、临时给首胜+23张。每支都从 P184 同一份已实付43兵、第19关已胜的完整 `rts_save` 出发，实际打第20关，再用真实市场、扩村、在线出生、调岗、训练队列和编队连续打到当前正式第29关。候选只存在于 VM 的 `CFG.enemies[19]`，没有写入玩家文件或永久存档。

## 数值选择和同源入口

当前村庄Lv6、人口与容量20/20、地契0、金币57、5粮工和6煤工。`settlementBatchPreview('village',2)` 对下一档逐级报价 **11+12=23张地契**。因此+11是“第20关后获得一档住房”的最小自足候选；+23是“不挪6名煤工而新增两名粮工，使22人/7粮工可供73人编队”的最小两档候选。不给奖仍能通过现有市场购契扩到22人，是经济保底对照。出生没有被奖励直接触发：先实付扩村，随后有粮在线10秒才由20人增加到22人。

P184战前原文 SHA-256 为 `dcf5099ad40f598bd63a8b3753b63290a085d8e509be661abab979a79454a29c`。当前正式第20关敌阵三系各`[8,6,4]`；流1/15在当前同速排序规则下真实首胜分别损18/28人，回合、RNG调用与[P216正式抽查](combat-order-downstream-p216.md)逐项相等。第20关木/石/粮实入分别为0/6/约2994.557；三支同流除地契实入0/11/23外，初战数值一致。两条流来自**同一份付费档**，不是两个独立玩家或胜率样本。

三支都在第20关胜后马上以相同目标扩村两级、保留木3/石3/煤6/铜3并把粮工升至7。无奖和+11支只购买尚缺的地契：售木实际合计分别22430和11430，花金币2300和1200；+23支无须售木购契。每笔市场交易、扩村、岗位动作及战前/后都保存重载。随后第21关补至青铜15/侍从骑士15/游侠13共43人；第22关起补至青铜15/侍从骑士15/民兵15/游侠28共73人，均经合法编队弹窗入场。所有已产士兵均由队列逐次真实扣费。

相对无奖，同流+11至第29关节省约1222–1223模拟在线秒，+23节省约1993–2118秒；这是这套“先统一扩至22人、再补满同一阵容”的操作策略，不能推断玩家平均用时或候选最优策略。到第22关战前，六支都是22人/7粮工/6煤工和同一73人编队；粮产17.325/秒、满编军粮约12.915/秒、居民口粮2.2/秒，动态净粮约+2.210/秒。第29关正式`帝国军校学徒`的胜负和战损同流完全一致，说明本批奖励只改变经济到达时间与库存，不是改第29关胜率。六支结算时仅余13–14兵，**第29关后的补军、败战、驻军与第30关尚未检验**。

速度与粮食缓冲存在取舍。流1的+23支在第22关训练付款后最低粮0.188，无奖支在同阶段最低约1681.856；直接把节约的等待时间全部兑现为提前开战会使库存显著更薄。流15各支在后段付款后均曾低至0.008–0.071。不能只看正净粮就断言补兵过程安全，也不能把+23写成确定优于+11；下一次决策应同档比较主动缓冲等待、短时离线、驻军和第29关重损后的恢复。

一次性语义走现有 `S.defeated` 首胜门：两种候选真实首次结算的地契和胜场记录同次保存，重载后对同一已胜档再调用结算不增加地契；另把[P216](reports/data/p216-combat-order-downstream.json)现行旧第20关胜档载入候选 VM，仍为0地契，重复结算也不追溯发奖。后两项是隔离的重复结算边界断言，不是第二场自然战斗。[既有L3专项测试](../../tests/progression/population_first_clear_reward.js)还覆盖主档/备份写入失败回滚；本批未另造第20关故障夹具。
