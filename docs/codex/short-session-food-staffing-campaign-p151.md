# P151：四学者短时战役的连续粮工与败后恢复（2026-09-26）

## 方法与范围

从4学者科研优先的零胜场人口路线真实`save()`终档出发，使用当前P102军备准备、生产、训练、战斗、胜后补兵与离线结算函数，短时profile为每600在线秒后离线28800秒。只在受路径校验的临时P102副本中插入岗位动作：每次待离线结算前，如粮工少于3人，就通过真实`setPopAlloc()`从指定的石／煤／铜岗位转人，使粮工到3，并在后续继续保留3人。三个来源分别独立重放。

P102每次运行都比较三种原有测试分支：当前岗位基线（军备准备后已有3粮工、不调岗）、开发侧L3首胜+6地契的前置金属岗位（2粮工、被测策略调到3）、同一开发奖励的前置粮食岗位（原有4粮工）。+6地契只在开发探针中模拟、未进入玩家运行代码。每条分支首次战败后调用真实补兵并等待600在线秒，再重试同一关；战斗随机值固定0.5。

**奖励口径补充（P155，2026-09-26）**：这里的“当前岗位基线”仅指当前岗位分配，不是当前线上奖励基线。P102在三个分支的每场胜利后都向隔离存档注入`ceil(关卡ID/10)`张基础候选地契；前置金属／粮食分支另于L3胜利后加6张。当前`levels.js`关卡奖励没有地契字段，所以本报告所有关卡结果均是在测试候选基础奖励下测得；+6虽是额外开发敏感度，但其余分支也不等于无地契奖励。无玩家奖励或存档改动。

所有分支第9关均以15步兵／13猎人／15青铜守卫出战，固定随机值0.5下该场首次败北，战后仅剩步兵15、猎人0、青铜守卫0。P102真实败后队列、600秒在线恢复和同关重试均成功。探针停在重试结果，不继续挑战第10关。

## 设计含义与边界

这组四学者会话里，维持至少3名粮工足以让金属岗位分支跨过连续7个8小时离线窗；从石、煤、铜抽1人都重现同一结果。窗口供给问题由此从第4关后的直接阻塞，推进到第9关实际战斗损兵／军力阈值。首败后600秒能赢回第9关，证明该单次恢复支路可达；由于探针在重试后停止，尚不能把它说成能继续稳定打到第10关。

此结论限于一个人口档、四学者、固定随机值、P102的目标编队和开发侧奖励分支。没有对比长时间保持石／煤／铜岗位的产值、下一轮补兵材料或多个章节；前置+6地契不是当前奖励。粮工数量只作为短时军备恢复的节点候选，不形成全局配置，不调整自然出生率或首通奖励。
