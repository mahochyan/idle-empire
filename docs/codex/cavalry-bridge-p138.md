# P138：L11 后骑兵解锁桥与人口检查点（2026-09-25）

P137的固定编成在L16首次战败。P138用种子3、frontloadedFood、每胜600模拟在线秒续跑同一P102路线，在L12前通过真实动作建骑兵训练场、完成建造、解锁`cavalry_t1`、训练一名骑兵，并走真实编队、战斗、损兵与补兵。根目录P102探针和游戏模块只复制到受路径校验的系统临时目录；只有临时副本中的开发探针被插入骑兵动作，仓库里的运行时代码和P102原文件不被改写。原始路线和输入SHA-256见[回放数据](reports/data/p138-cavalry-bridge.json)。

L11胜后600秒结算点的探针状态为19/19人口、木730／石1600／粮3000、科技3000、战功56、已击败1个Boss。实际`buildAct('stable')`支付木220／石160／粮180并用7次真实tick完工；`unlockUnitRoot('cavalry_t1')`再支付木300／石200／粮250、科技250和战功8。随后`train('cavalry_t1',1)`支付木120／石80／粮150，并在1次真实训练tick后产出首骑兵。当前工作区启用的`unitCapBoost`使T1骑兵上限为19；本回放只训练1名，不能把19当作该路线的实训人数。解锁所需Boss、时代、科技和资源门均由游戏动作函数检查通过。

带一名骑兵后，同种子路线从P137的L16败改为L16五回合胜，但该骑兵在L12–L16每场都阵亡，需在600秒／胜的既定补给窗内训练回1名。L17遇到63人、HP63、加权攻击567的敌阵后，两回合失利，故这只把首败从L16推至L17，并未闭合第二章持续军力。L16虽然叫“骑兵斥候”，实际生成的兵种仍是步兵和弓手；这次胜利证明额外T1战力在该种子里有帮助，不证明其克制关系或敌阵命名准确。

人口在L12开战前为19/19；在P102开发侧奖励模型下，L12胜利发2地契、真实扩建支付10地契，后续600秒自然出生使L13开战前达到20/20。L13–L16容量与人口维持20/20。这个观测**依赖尚未接入玩家代码的首通地契模型**，不是当前线上增人口节奏的实证。它支持继续按“经济保底、战斗加速”验收容量来源，但不支持现在调整人口速率或把通关设为唯一增人口入口。
