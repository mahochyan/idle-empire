## C2. 体力系统（行动力）

- 头部 `.power` 显示的不是战力而是**体力**（@1834246 原文 '体力' + Power[0]）
- 城镇建房/政策操作扣 5 体力（@1579012 `Power[0]-=5`，"体力-5"提示；autoHouse 自动化面板可静音该提示）
- 体力不足 gate：`Power[0]<5 → "体力不足"`（@1578315，量子时代解锁后免体力 gate 分支【推断】）
- 体力上限科技：LvMax 50 级，每级 知识1000+勋章10 → 上限+10（@1137432）
- 黑市奖励池含"获得:体力x20"、"获得:小刀x3/5"（@1699708，小刀=黑市砍价货币）

## C3. 杀戮值——风险收益调节器（@1179423 killValue 表）

FAQ 原文：**"杀戮值在怪物右上角，杀戮值越高，怪物越强，奖励越多"**
配置：Init 0、Value 100（每级加成基准）、Rate[4000,2000,1000,0]（击杀 N 怪升一档，越杀升档越快）、AddHP/ATK/DEF +5/档、AddAmount 15（数量+15/档）、GetPer 40%（获取率修正）；每类怪挂 KillValueID（山贼系/六艺兽系/势力系/杀戮之神1-6/众神之主 加值 10000）。
**"击杀善良、怨恨的敌人，会获得更多的杀戮值"**（Tip）——怪物带道德标签驱动 farming 强度。这是把"刷多久"变成显式难度旋钮的设计。
**深层实证（战斗代理 §5，父代理比对通过）**：杀戮值对怪物强度的阶梯倍率 ×1.2→**×180**（@1373493，超指数橡皮筋），而奖励侧 getKillPerReward **封顶 ×8**（@1375671）；另有 KillValue≥1000 → 波次倍率 1+2⌊KV/1000⌋（@1362250 亲验）。高杀戮段=风险收益严重倒挂的软性刹车。

## C4. 秒杀/记录系统（挂机核心 UX）

- `battleQuick` 开关：**"开始秒杀--可打赢的怪物数据"**、"秒杀时不会覆盖记录"（@2608182）——对已验证可胜的怪直接跳过战斗动画结算
- `battleRecord`（七日战争 battleRecord 开关）：记录首杀数据用于回放
- 防滥用：`"怪物数据超出记录，无法秒杀"`（存档数据与当前战斗数据不符时拒绝）
- 战斗刷新：battleRefresh001/002 双计数（免费/付费池【推断】），"刷新次数不足"；"战斗并处于纪录或秒杀中，无法使用刷新"
- 神器特效里的条件秒杀："自己攻击大于敌人时，0.1%直接秒杀（进场生命每有280，概率+0.1%）（仅对最大生命<自身10倍的敌人）"（@1078167，千殇枪系）

## C6. 工人 tick 模型（@1277892）

```js
window.setInterval(() => addResourceWorker(workerID), WORKER_CFG[workerID].Interval)
```
每个工人独立定时器，周期由配置 Interval 字段决定（经济章节给全表）；350007（幸福感线）例外走全局调度。`clearTimer` 支持政策/自动化批量关停——autoCollect 面板即操作这套定时器。
